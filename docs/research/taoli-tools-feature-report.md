# taoli.tools 功能取舍报告（面向开发者）

> 证据说明：本报告在四路调研基础上做了二次核验。docs 全文来自 `gh api repos/taoli-tools/taoli-tools-docs`（61 个 md，2026-07-31 仍在提交），本报告引用的关键口径（VA/VB 算术、Flat 判据、MinA/$MaxA 语义、差价公式、3s/9s 陈旧度、N 系数、手续费 2 倍公式、TradFi 支持表、VIP 价目、150ms ping）均已逐条在源文件中复核。仅来自 JS bundle 反混淆的单路结论已标注「待核实」。

## 1. taoli.tools 是什么

它是 aliez-ren 的前作，官方自我定义就是一句话：**「半自动化 U 本位对冲套利工具」**，核心功能只有一个——一键双边下反向对冲单（`docs/index.md`）。同一份文档的「不是什么」章节明写三条：不是无风险摇钱树、不能帮你全自动赚钱、**不能自动化执行策略**。它甚至连杠杆倍数都不给你在工具里调（`trading-page-guide`：「杠杆倍数需要去交易所里调整，无法在工具里进行调整」）。

所以两个产品是**同一个作者的两次相反下注**：

| | taoli.tools（前作） | qqq.bot（新作） |
|---|---|---|
| 定位 | 半自动**驾驶舱**：人盯着，Loop 只在差价满足时开火 | **自动驾驶**：策略规则引擎 + ADL 自动响应 + 自动调杠杆 |
| 换取的东西 | 用**广度**换深度：30 家场所 × 4 种市场类型（现货/逐仓/全仓/永续）× 37 条链 × TradFi | 用**自动化深度**换广度 |
| 强项 | 看板、执行原语、风控展示、单腿救援 | 收敛循环、规则引擎、事后自动降档 |
| 短板 | 无自动化、无杠杆控制、榜单不配对不扣费 | 无年化、无流动性维度、无告警、无事前风险视图 |

**结论：这两个产品的能力是互补而非重叠的。我们要做的是「taoli.tools 的看板与执行原语 + qqq.bot 的自动化」，两边各取一半，再补上两者都没有的那一块（见第 7 节）。**

同时必须记住一个负结果：**借贷挖矿、现货网格、活期理财、Launchpool、新币挖矿、量化信号、风险计算器、回测、模拟盘、批量账户编排——taoli.tools 一个都没有。** 全量 grep 61 篇文档，「借贷」只命中现货杠杆利息记录导出，「空投」只命中首页一句用途说明「刷交易量，撸空投或返佣」。不要再花时间去那边找这些东西。

## 2. 必须做（must）

按重要性排序。

### M1. 资金费率的结算间隔归一化 + 年化切换

**是什么**：榜单的资金费率列本身是一个基准切换器（`8H` ⇄ `1Y`），配合独立的「间隔」列展示各合约的结算周期。程序内部枚举了完整 ISO8601 周期常量（PT5M / PT15M / PT30M / PT1H / PT2H / PT4H / PT8H / PT12H / PT24H）。

**为什么必须**：这是 qqq.bot `funding-spread` 最直接的硬伤。我们六家里 Binance 主力 8h 但热门币 4h/1h、Bybit/OKX/Bitget 混用、Gate 部分 1h——不归一化的话 1h 的 0.05% 和 8h 的 0.05% 会被排在同一行，用户会**系统性选错币**。

**实现要点**：`rate_8h = rate_raw × 8 / interval_hours`；`APR = rate_8h × 3 × 365`。间隔从各所合约信息接口取（Binance 走 `fapi/v1/fundingInfo` 的 `fundingIntervalHours`）。**注意 taoli 的 1Y 只是朴素 `×3×365`，不复利、不扣费——我们不能止步于此（见 M7 和第 7 节）。**

### M2. 流动性容量闸门（未平仓额 / 24h 成交额）

**是什么**：榜单顶部两个对数滑块 `未平仓额 >= $X`、`日成交额 >= $X`，默认 $1M，先过滤再排序。第三个滑块按结算间隔过滤。

**为什么必须**：资金费年化榜的头部永远是垃圾小币——年化 300% 但 OI 只有 20 万刀，进 5 万刀就把费率打回去，还可能被拉盘爆空单。**没有容量维度的榜单就是垃圾场**，qqq.bot 完全没有这一层。

**实现要点**：对数滑块（min=2 max=10 step=1，值 = 10^n，label 用人类可读缩写）比数字输入框好得多——把「几个数量级」变成一次拖动，天然防手滑多打一个零。NiceGUI 的 `ui.slider` 直接可用。**默认开启，不要默认关闭。**

### M3. 资金费率上限 / 下限（cap / floor）

**是什么**：独立的「上限 / 下限」列，展示该合约资金费率的交易所硬性封顶封底值。

**为什么必须**：这是判断「极端费率能不能持续」的一票否决位。看到 -2% 很兴奋，但如果该合约 floor 就是 -0.75%，那个数要么是脏数据要么马上被夹回去，年化外推完全失真。同样是当前 0.3%，cap ±0.5% 的币和 cap ±2% 的币风险完全不同。

**实现要点**：Binance `fapi/v1/fundingInfo` 返回 `adjustedFundingRateCap` / `adjustedFundingRateFloor`，其余五家有对应接口。合约信息接口一次性拉、低频刷新，成本约等于零。

### M4. 报价陈旧度分级 + 硬阻断

**是什么**：买一卖一价正常灰色，**3 秒**前的数据变黄，**9 秒**前的数据变红；超过 3 秒未更新直接 `Price expired` 拒绝下单。另有 5 分钟阈值的 Stale 通知（每 60 秒检测）。每腿带 `⟳` 强制刷新。

**为什么必须**：跨所套利最隐蔽的杀手是「一边 WS 断了但价格还挂在屏幕上」——拿陈旧价算出的差价是幻觉，照着下单必单腿必亏。HTX/Gate 的冷门币订单簿几分钟不动是常态。qqq.bot 的 500ms 收敛循环里没有显式的行情时效门禁，等于在用可能过期的价格反复开火。

**实现要点**：一个时间戳比较 + 三档颜色 + 一个下单前断言。3s/9s 这两个阈值是 1.5 年运营验证过的，直接沿用。

### M5. N —— 合约面值换算系数

**是什么**：建对时的一个参数，「一个单位 A 等于多少个单位 B」。文档原例：A 是 1MCHEEMS、B 是 1000CHEEMS，N 填 1000。

**为什么必须**：1000PEPE / 1MPEPE / PEPE 这类不同面值命名在六家 CEX 之间极其常见，**搞错就是 1000 倍的仓位错配，一次就爆**。不能靠 symbol 字符串猜，必须在建对时显式建模。

**实现要点**：N 要在**两处**都乘上去——差价计算和持仓平衡判定。镜像复制交易对时 N 自动取倒数。

### M6. 中点归一化差价公式 + 历史差价时序

**是什么**：
- `-A+B` 差价 = `(A_Bid1 - B_Ask1) × 2 / (A_Bid1 + B_Ask1) × 100`
- `+A-B` 差价 = `(B_Bid1 - A_Ask1) × 2 / (B_Bid1 + A_Ask1) × 100`

分母是两者之和（即中点的 2 倍），**不是以 A 为基准的比率**。点击方向标签可打开该方向的历史差价图，可选蜡烛宽度和用 OHLC 哪个字段算差价。

**为什么必须**：公式本身要抄——双边都在动的时候中点归一化比单边基准更对称、无方向性偏差。历史分布是定阈值的**唯一理性依据**：不看分布拍脑袋设 0.5%，要么永不触发要么天天亏。qqq.bot 只有 `latest-spread` 快照。

**实现要点**：我们有 Python 后端 + SQLite，存差价时序比它在浏览器 IndexedDB 里存容易一个量级——这是可以直接拉开差距的地方。

### M7. 手续费的真实建模（门槛公式 + 计价币种）

**是什么**：三件事。
1. **盈亏平衡门槛**（FAQ 原文核验）：两个方向的预设差价之和 ≥ **2 ×（A 手续费 + B 手续费）**。原例：A 0.1% + B 0.05% → 两个差价之和需 ≥ 0.3%。
2. **实得差价 = 预设差价 + VA + VB**（下单文档原例：0.5% + (-0.1%) + (-0.2%) = 至少赚 0.2%）。
3. **手续费计价币种**：买入现货用**币**扣手续费，卖出现货/做多合约/做空合约三种情况扣 **U**；平台币抵扣（BNB / GT / POINT）和链上 Gas 也计入 PnL。FAQ 专门解释了「现货总是少点零头」就是这个原因。

**为什么必须**：qqq.bot 的机会榜连手续费都不扣，这是它最大的谎报来源。手续费币种不建模，账永远对不上，而且会**掩盖真实盈亏**（用户以为赚了其实在亏）。GT/BNB 抵扣直接影响 Gate/Binance 的实际成本。

**实现要点**：把 `2×(feeA+feeB)` 这条红线在 UI 上直接算给用户看，而不是像 taoli 那样只写在 FAQ 里。**另有一条影响净收益的关键事实（待核实）**：多家所标注「使用 API 下单时返佣更低」（Gate 合约 64%→44%、Bitget 合约 60%→50%），意味着我们跑 API 拿到的返佣比页面标价低一档，算净收益要按 API 档位算。

### M8. 单腿防线三件套（预检 + 闸门 + 救援）

这是这类工具**唯一真正会亏钱的失败模式**，三条必须一起做：

**(a) Flat 持仓平衡预检**：勾选后每次双边下单前检测两腿是否平衡，`|PosA| 与 |PosB| 之差 ≥ Size` 则黄字警告、不下单、**但不中断 Loop**。判平衡的官方口径（文档原文）：**`Position + 所有未成交订单总量，AB 两边加起来是否等于 0`**——未成交挂单必须计入，这是限价模式下最容易出现的隐形单腿（A 已成交、B 还挂着）。

**(b) 四道仓位闸门**：`MinA/MaxA`（币本位）+ `$MinA/$MaxA`（U 本位），四个同时填写是 **AND 关系**。只约束 A 腿。**黄色未成交挂单也计入**。触发时黄字暂停下单但**不停止 Loop**——价格回来自动恢复，不用人工重启。

**(c) 一键救援并计入 PnL**：红色错误行按修饰键出现 `✓`，后面直接跟着需要补的方向和 size，点击市价补单；未成交挂单的 `⨯` 取消按钮按修饰键变 `✓` 市价追单。**关键是文档明写：在工具内操作成功的补单/追单，可以正确计算到其对应的 PnL。**

**为什么必须**：币本位闸门在币价暴涨时失效（数量没变市值翻倍），U 本位闸门在币价暴跌时失效（市值缩水数量堆积），两个 AND 起来才是真闸门；qqq.bot 只有单向棘轮式 target，表达不了「区间」。救援按钮的价值不只是省事——**任何绕过工具的手工补仓都会污染 P&L 账本**，这是对账功能的隐含前提。

**实现要点**：抄它的判据，但**修掉它的两个坑**：追单在无改单接口的所上是「先撤再下」（非原子，可能撤了没重下），我们要做成幂等重试；补单/追单**必须加二次确认**（taoli 明确没有，文档自陈「可能需要点击多次」）。

### M9. 三级消息行 + 可重放的错误上下文

**是什么**：每个 Pair 下方一行状态消息，灰=可忽略 info / 黄=需留意但无大碍 warn（不中断 Loop）/ 红=至少一边失败 error（停止运行、仓位单腿）。重要覆盖不重要，**刷新页面后仍在（持久化）**，可点 `⨯` 关闭。红色消息里存着完整的 `{ticker, side, size}`，所以才能一键重放。

**为什么必须**：把「报错」变成「可操作」的关键就是错误对象里存下足够重放的上下文。成本极低价值极高。三色分级 + 覆盖策略也比堆一个日志列表实用得多。这是我们的错误处理应该直接采用的模型。

### M10. 通知矩阵：4 通道 × 6 事件（含明确轮询周期）

| 事件 | 触发条件 | 检测周期 |
|---|---|---|
| Order | 工具内触发下单（**注意不是成交**） | 事件驱动 |
| Warn | 现货余额不足 / 超 MaxO、MinA、MaxA / A then B 时 A 出错 | 事件驱动 |
| Stale | 价格 5 分钟没更新 | 60s |
| Error | Pair 下方出现红字 | 事件驱动 |
| Risks | Risk 出现红字，或勾了 Flat 但两边不平衡 | 15s |
| Price | 价格超出设定安全范围 | 30s |

通道：Web / Telegram Bot / Lark 飞书 Webhook / Bark。

**为什么必须**：qqq.bot 已知能力里**完全没有告警层**，这是纯增量。这套分类的每一类都对应一条真实的亏钱路径，颗粒度是 1.5 年运营打磨出来的——尤其「下单触发」和「成交」分开、「价格不动」（说明 WS 断了）单列、「不平衡」单列这三个划分。周期值（60/15/30）直接抄，省掉自己调参。

**实现要点**：我们已有微信推送基建（`crypto_social_tracker`），把微信当第五通道加上去即可，比 taoli 还全。**坑**：TG Bot 创建后必须被用户手动点一次 Start 才有推送权限。

### M11. VA / VB —— 每腿独立价距

**是什么**：勾选 Limit 后启用。VA、VB 分别是 A 腿、B 腿委托价相对买一/卖一的偏移（百分比）。`V<0` 超价吃单（快但可能亏）、`V=0` 贴买一卖一挂单、`V>0` 通常不立即成交（做 maker）。留空该腿走市价单。超出交易所限价范围时输入框变红但仍可尝试下单。

**为什么必须**：这是全文档最有价值的一个设计——它把「**我要多大差价才动手**（目标）」和「**我下单有多激进**（执行）」拆成两个正交旋钮，还能一腿吃单一腿挂单（贵的所吃单、便宜的所挂单赚 maker 返佣）。qqq.bot 只有 FOK 限价单，没有任何等价表达能力。而且 V 值直接决定保底利润的下界，是**可计算、可回测**的。

**实现要点**：配合 M7 的公式，实时展示「按当前差价，这一单预计净赚 X USDT（已扣双边手续费）」。

### M12. API Key 配置 runbook + 启动自检

**是什么**：文档给了逐所的权限配置清单，两条铁律 +六家共性 + 各所差异：
- 铁律：**一定不要开启转账和提现权限**（DANGER 级）；建议开 IP 白名单。
- **六家全部要求「单向持仓」**。
- Binance：必须先填「只访问受信任的 IP」或取消「默认安全限制」才能勾权限；**经典账户和统一账户权限勾选不同，更改账户类型后必须重建 API Key**。
- OKX：只勾读取+交易，账户模式需切合约/跨币种/组合保证金，永续只支持全仓。
- Gate：必须先升级统一账户。Bybit：选「读写权限」并勾 UTA 全部四项。Bitget：USDC 合约和 U 本位合约分别设持仓模式。
- Gate/Bitget 市价买现货传入的是 **U 的数量而非币的数量**，会导致实际成交量与 Size 有出入。

**为什么必须**：这是踩坑攒出来的，直接抄进引导流程能省掉海量客服。最关键的是**把它做成程序自检而不是文档**：保存 API Key 时自动检测持仓模式、账户类型、权限位、时钟漂移（`recvWindow` 类报错说明本机与交易所时差 >5 秒）、ping 延迟，**当场报错而不是等下单失败**。

## 3. 应该做（should）

### S1. Sequence 腿序控制（Parallel / A then B / B then A）
串行模式下前腿失败则后腿不下单，且 **Loop 不停止（只警告）**。文档建议「哪边容易失败就优先哪边」。我们六家里 HTX/Gate 的 API 稳定性明显差于 Binance/OKX，先打脆弱腿能显著降低单腿率。实现成本很低（一个枚举 + await 顺序）。**但必须连带做对账**：文档明确警告「如果交易所 API 返回成功但实际没下单成功，仍会被认为成功」——不解决这点，A then B 反而制造新的单腿来源。

### S2. 双向同时 Loop（用价差做市）
同一个交易对的 `-A+B` 和 `+A-B` 可以**同时点亮 Loop**，两边阈值不必相同、允许一边为负。差价来回震荡时两个方向反复吃——本质是在价差上做市，而不是「开仓→等→平仓」的单次往返。工具里根本没有「开仓/平仓」概念，只有两个方向。判据就是 M7 的 `2×(feeA+feeB)`。
**qqq.bot 结构上做不到这个**：它的规则引擎是棘轮式的、target 只能单向调。跨所价差是均值回归的，双向 Loop 才是价差套利的正确形态。我们的规则引擎应支持每个 pair 挂两组独立阈值，并在 UI 上直接算出「两边阈值之和是否过线」。

### S3. Risks 三件套（ADL / 归一化 MR / 爆仓距离）
每腿常驻显示：ADL 自动减仓优先级 5 档（**仅 Binance / Bitget / Bybit / Gate / OKX 有数据——正好是我们六家里的五家，HTX 没有，别为它白折腾**）、MR 保证金率、Liq Price 清算价，红/黄/绿/灰四色。
两个可直接抄的归一化决定：**MR 统一到币安口径「权益/保证金」，数字越大越安全**（其他所通常取一次倒数），>100 时不显示；**爆仓距离** = `市价 = (买一+卖一)/2`，然后 `爆仓价>市价 ? 爆仓价/市价 : 市价/爆仓价`。MR 阈值分档：>5 灰、>2 绿、>1.5 黄、否则红。
**这和 qqq.bot 是互补关系**：qqq.bot 是 ADL **之后**降 target 并锁 reduce-only（事后止损），taoli 是**事前**把你在 ADL 队列里的位置摆出来。两个都要。

### S4. 现货杠杆腿 + 借币利率并入净收益
A/B 两腿各自可以是 Spot / Isolated / Cross / Perp 任意组合。永续腿的 Fee 位显示下次资金费，现货杠杆腿显示**每小时利息**，可导出 Lending 利息 CSV。
**明确一件事：这不是理财挖矿产品，是保证金腿的成本项。** 它只做到「帮你把借币利息算进成本」这个记账层级，没有任何「借 A 币放 B 池吃利差」的策略。价值在于打开 spot-perp basis 和「现货杠杆做空 + 永续做多」这类玩法。
支持面（官方支持表核验）：**我们六家里 Binance / Bybit / Bitget / Gate 有现货杠杆，OKX 和 HTX 没有**。优先级排在纯 perp-perp 之后——先把双永续跑通再加。不要为此专门做一个借贷模块。

### S5. 一所多账户（但修掉它的主键坑）+ 全账户总览
它的模型是 `Unique Name + 交易所枚举 → 实例`，同一交易所可加任意多次（= 多 API Key / 多子账户）。保存即验证（绿字显示资金量 = 成功，红字**拒绝保存**）。`⟳` 测 ping，建议 <150ms。
**两个明确的坑要修**：(1) 文档警告「重命名可能导致已有 Pair 和 P&L 出错」——说明它**拿名字当主键**，我们必须用稳定 ID + 显示名分离；(2) 它**没有任何账户分组、批量下单、批量配置、统一风控**，多开靠开多个浏览器 profile。
我们至少要有一个**全账户总览**（总权益 / 总敞口 / 各所可用余额），这是低成本差异化点。另：整份文档只有 Lighter 一家提到子账户（Account Index，0=主，1+=子），**六家 CEX 的设置文档完全没有子账户概念**——说明子账户不是这个赛道的刚需，但做了就是差异化。

### S6. 报表三件套 × 三种交付
Trading（日期总表 + 按 Pair 的 A/B 分表）/ Funding（最近 7 天 + 按 Ticker 分表）/ Lending（必须先选 Ticker），每类三种交付：**页面直接渲染 / 推送给自己 / 下载文件**。
两个巧思值得抄：(1) **把 Funding 和 Lending 拆成独立账本**——资金费套利的收益来源和成本来源就是这两块，混在 PnL 里看不清；(2) **「页面预览」这一档**——用户 90% 的时候只是想看一眼，不想下载文件再开 Excel。我们跑在服务器上，「推送到手机」这一档尤其香（不用远程桌面就能拿到报表）。

### S7. 价格安全区间（每腿独立上下界）
为 A 和 B 各设一个 `下限 ~ 上限`，超出触发 Price 通知（每 30 秒）。这是**无人值守时的兜底闸门**——币价跑到离谱区间说明假设已破，比单纯止损更适合对冲场景。qqq.bot 没有对应物，实现成本几乎为零。

### S8. 交易对搜索的三个细节
末尾加 `/` 启用**精确匹配并展示全部结果**（普通搜索只给 50 条）；**已下架标 `!`、异常状态（盘前盘后、只减仓）标 `?`**；不搜索时默认显示当前有持仓的交易对。
下架/只减仓标记能直接防住「开了仓平不掉」这类事故——Bybit 的 PreLaunch、Binance 的下架公示期都会踩。

### S9. 镜像复制（A/B 互换且参数全部同步变换）
复制出一个 A、B 交换的 Pair，同时 **N 自动取倒数、MinA 和 MaxA 自动对调、Sequence 翻转、预设差价互换**。这是套利工具的杀手级细节：开完 `-A+B` 想准备反向平仓单，一键生成参数全部正确取反的对照 Pair。这个功能的存在本身说明作者踩过手动改错的坑。

### S10. 修饰键作为「第二层 UI」（但加确认）
可配置 Shift/Ctrl/Alt，按住时整屏控件切换成另一套：MinA/MaxA → $MinA/$MaxA、取消挂单 → 市价追单、报错行 → 一键补单、删除/复制/最小化 → 上移/镜像复制/下移、Risks → 持仓均价、Fee → 费率上下限、Last → 价格安全区间。按住时中央列出现蓝色 inset ring 提示「你在第二层」。
这是它把极高密度塞进一屏的核心手法，也是把危险操作藏在一层门槛后的安全设计。NiceGUI 用 `ui.keyboard` 可实现。**抄机制不抄鲁莽——它的追单和取消都无二次确认。**

### S11. 配置导出 / 导入（文件 + 独立密钥双因子）
Export 下载 JSON **同时把一个 `tt-` 开头的密钥串复制到剪贴板**，Import 需要同时提供文件和密钥。内容排除登录 Token 和 P&L。文件与解密密钥分离投递是备份含 API Key 配置的正确做法——文件泄露单独没用，也防止用户把带密钥的 json 随手丢群里。成本约 30 行代码。

### S12. 充提状态监控（前作的空白，我们的机会）
taoli 把这个**外包给了第三方 bot**（`third-party-tools.md` 里的「币探——查询/订阅充提状态&指数成分」）。但**跨所搬砖最致命的失败是搬过去发现提币关闭了**，这是硬前置，必须内建。六家 CEX 的 currencies 接口都有 `deposit/withdraw enabled` + 链选择 + 到账确认数字段。

### S13. 部署与延迟纪律 + 显示/计算解耦
交易所 ping **<150ms**，超了上服务器；推荐**亚太-东京**（「大部分交易所的服务器都在东京」）；2 核 4G 起；时钟漂移 >5 秒会报 `recvWindow`/`timestamp` 错。我们是服务端程序，可以把「每个所的实时 ping」做成常驻指标并在超阈值时降级（禁市价单、拉大 V 参数）。
另有一条实现纪律：**Loop 实际间隔 = max(下单到确认耗时, 设定间隔)**（避免设了 100ms 就真的每 100ms 无脑打一发、堆积未确认订单）；**Display FPS 只影响显示、不影响差价计算**——这条对 NiceGUI 特别重要，UI 刷新频率必须和策略循环彻底分开，否则前端拖垮后端。

### S14. 移动端只读监控视图
taoli **零响应式**（`min-w-254`~`min-w-358`，差价图 dialog 最小 1016px），官方给的移动方案是「买台 Windows 服务器远程桌面连上去」。这是明确的可攻击面——**套利用户最需要移动端的时刻恰恰是出门在外仓位出问题时**。我们至少要做只读监控（持仓 + 敞口 + 风险 + 一键平仓），不必做完整下单。

### S15. UI 语义约定（低成本高一致性）
**A = 蓝、B = 橙**贯穿全站（列表、差价图、资金费面板高亮），用户不用读文字就知道在看哪条腿——这是最该抄的一致性规则。等宽字体让数字列天然对齐。颜色只有四档语义：灰（忽略）/ 绿（安全）/ 黄（注意）/ 红（危险）。
主面板一行只有 **Position / Fee / Bid-Ask / Available / Risks** 五个字段——这就是对冲套利真正要盯的全部。列头本身即「点击强制刷新」按钮（`Position ⟳`），省掉一排工具按钮。
下单按钮做成**状态机**：`Once` 点击后变 `Stop` 并高亮，两个按钮互斥禁用，运行中禁用该方向的参数输入。创建任务用**底部常驻单栏 + Advanced 折叠**（默认 3 个控件），而不是模态向导。
**但要修它的短板**：字符按钮（⟳ ⨯ ◧ ◫）对新用户零可发现性，文档不得不用一整页解释每个符号——保留密度但给按钮加 tooltip；13 个裸 number input 无引导是它劝退新手的主因，我们每个参数要带 inline 说明 + 单位切换按钮（而不是 A̳ A̿ U̳ U̿ 这种上标）。

## 4. 可以考虑（maybe）

- **交易对配方字符串**：搜索框粘贴 `BN-P:BTC/USDT+OK-S:BTC/USDT` 自动填充 A/B 两腿。群友可以贴一行文本互相分享机会，对方粘贴即建仓。成本极低、社群传播价值高。**（待核实：仅来自 JS bundle 反混淆，docs 无记载）**
- **战绩小票分享卡**：按日化收益率分七档稀有度（≥16% 日化直接叫 SCAM，很聪明的自嘲式风控提示），币种和交易所**默认打码**、点击才展开——解决了晒单的隐私顾虑，用户敢发才有传播。**（小票功能本身 docs 确认存在；稀有度分级来自 JS bundle，待核实）**
- **资金费历史面板**：CSS 渐变画时间比例条形图（零依赖零布局抖动），缺失的结算周期用垂直留白表达；**附带展示该永续合约的指数成分**（成分所 + 价格 + 权重）——能提前发现某个永续的指数只挂在一两家小所上，这是被操纵/插针的高危信号。这个「指数成分」是个隐藏彩蛋，价值不低。
- **P&L 横向流水条**：滚轮转横向滚动；**只在卡片可见时才轮询 fills，算出非 0 结果就停止**——六家所的 fills 接口都有限频，这个懒加载模式能省大量无用请求。**（待核实：JS 反混淆单路）**
- **差价图三窗格**：差价基线图（叠加双腿溢价指数虚线）+ 双腿 K 线 + 镜像成交量，**资金费结算点画成半透明竖线标注**——一眼看出差价的周期性是不是被资金费驱动的。这是它最强的一个可视化。**（竖线标注细节待核实）**
- **TradFi 腿**（美股/指数永续）：官方支持表确认 11 家 CEX 全支持。做市商少、定价效率低，价差和费差比主流币大得多，且与 crypto 低相关。但有交易时段、分红调整、条款同意（Gate 必须先在所内同意条款 API 才返回数据）等一堆特殊逻辑，**不适合 v1，记在路线图上**。
- **子账户支持**（见 S5）。
- **私钥/API Secret 拆成 Head + Tail 两个输入框**：防剪贴板监听/肩窥的低成本手法，恶意扩展一次读取拿不到完整凭据。
- **Signer 架构**（若将来加链上腿）：签名服务与交易逻辑进程隔离 + HMAC-SHA256(`X-SIG`) + IP 白名单 + **硬编码合约白名单**。真正的安全价值在白名单而非 HMAC：EVM 侧 `tx.value != 0` 直接拒绝（禁止转原生币）、`to` 必须在白名单否则只允许 `approve` 且 spender 也须在白名单；SVM 侧每条 instruction 的 programId 都要命中白名单。**即使前端被完全攻破也搬不走资产**——这是「签名服务不信任调用方」的教科书实现。注意 README 说的 "Contract allowlist" 暗示可配，实际编译期固定，要改必须改代码重新部署。

## 5. 不建议做（skip）

| 项 | 理由 |
|---|---|
| **浏览器扩展 / 解除 CORS / `--disable-web-security`** | 纯前端架构的债。它要求用户装一个拥有 `*://*/*` 权限的 MV3 插件，或关掉浏览器最核心的安全机制——**这和它自己风险页里「恶意插件会偷走你的 API Key」的警告自相矛盾**。Python 后端零 CORS 问题，这是我们的结构性优势，应该在定位上明说。 |
| **自建 `/proxy?url=` 中转 + 缓存端点** | 同上，是同源策略的补丁。我们直连。 |
| **Docker + noVNC + Tailscale + VNC 远程桌面** | 「必须有个浏览器在跑」逼出来的形态。我们后台常驻 + Web UI 就行。（唯一可借鉴：docker secret 存密钥 + `networks: private: {internal: true}` 让签名服务无出口。） |
| **`--user-data-dir` 多浏览器多开** | 这是操作技巧不是功能。我们一个进程管 N 组 API Key，多账户应是一等公民。 |
| **浏览器本地存储作为唯一持久化** | **这是 taoli 最大的运维短板**：换浏览器 / 清缓存 / 硬盘满 = 配置和 P&L 全没（FAQ 第 13 条专门解释这个）。API Key 只有「一层简单的加密」（localStorage 里一个 randomUUID 派生 AES-GCM，**密钥和密文放在一起，实质是混淆**）。我们用 SQLite + OS keyring/主密码派生 + 定期备份，直接当卖点。 |
| **Telegram 登录 + 服务端 VIP 额度校验** | 它宣传「本地运行」，但**快速开始第 1 步就是用 Telegram 登录**，且服务端要汇总 UA/IP/UID 哈希/账户权益来卡额度——作者的服务挂了工具就不能用。我们是自用工具，不引入任何中心化依赖。 |
| **VIP 分级定价 + 全场所返佣分成** | 我们是自用工具，不抄商业模式。但记两条：**返佣才是这类工具真正的现金牛**，订阅费只是筛选器；**按 AUM 而非功能分级**（VIP1+ 无任何功能限制，纯资金量计价）是作者 1.5 年运营得出的结论——这类用户的付费意愿与资金规模强相关而与功能无关。 |
| **拿名字当主键 / 无二次确认的危险操作** | 明确的设计缺陷，见 S5、S10。 |
| **去找网格 / 理财 / Launchpool / 空投 / 量化信号 / 回测** | **它没有。** 别照着抄不存在的东西，也别在 v1 铺开这些。它运营 1.5 年、5487 人群、做到 VIP6 $1920/月，靠的是把「两腿对冲下单」这一件事的执行质量和风控细节做到极致。 |
| **开发者激励计划（VIP2 换社区小工具）** | 聪明的低成本护城河打法，但对我们这个阶段不适用。**有信息量的是那份获奖名单——它是一份反向需求清单**：社区自己动手补的（跨所价差实时监控榜、充提状态查询 bot、收益计算器、新币提醒）就是主产品缺的。这几样我们应该直接内建。 |

|---|---|---|
| 资金费**不年化不归一化** | ✅ **解决了** | 8H⇄1Y 切换 + 结算间隔列 + 内部 ISO8601 周期枚举。但 1Y 只是朴素 `×3×365`，不复利。 |

| **单腿裸奔** | ⚠️ **部分解决** | 给了四道防线：Flat 预检（含未成交挂单）、四道仓位闸门、Sequence 腿序、一键补单/追单且计入 PnL。**但它自己承认无论哪种模式都可能单腿**，且红字出现后 Loop 停止、需人工介入。它是「把不可控风险变成可控操作」，不是消除。qqq.bot 的 500ms 收敛循环自动补是另一半答案——**两者应该合并**。 |
| **无行情时效门禁** | ✅ **解决了** | 3s 黄 / 9s 红 / >3s 拒单 / 5min Stale 告警，四层。 |
| **无告警层** | ✅ **解决了** | 4 通道 × 6 事件 + 明确轮询周期。 |
| **明文/弱加密存 key** | ❌ **没解决** | 文档自陈「有一层简单的加密」，实现是 localStorage 里 randomUUID 派生的 AES-GCM——密钥和密文同处，等于混淆。风险页更是坦承「即使开了 IP 白名单、即使没有提现权限，黑客仍可通过**小币种对敲**转移资金」。**唯一真解决的是链上腿的 Signer**（进程隔离 + 合约白名单 + 拒绝 value≠0）。 |
| **N 面值 / 下架状态 / 时钟漂移这类脏活** | ✅ **解决了** | N 系数、`!`下架 `?`异常标记、`recvWindow` 排障都做了。 |

**两者都没解决的**：**跨所配对的净收益排序**。taoli 的榜单只列单腿原始费率，配对靠人脑；qqq.bot 的 funding-spread 不年化不扣费。这正是下一节。

## 7. 我们应该超越它们两者的地方

### 7.1 机会榜按第一性原理重做（最大的差异化窗口）

作者用 1.5 年验证了「资金费榜」这个入口有需求，但**把最难也最值钱的那一步留给了用户心算**。我们的榜单必须**默认**就是这三列起步：

1. **跨所配对**：同币种「A 所做多 / B 所做空」的**净费差**，而不是两条单腿让用户自己配。
2. **扣费净年化**：用用户实际 VIP 等级的 maker/taker 费率 + **API 档位的返佣**（不是页面标价档）+ 借币利率（若含杠杆腿），输出一个净 APR，并把 `2×(feeA+feeB)` 红线直接标出来。
3. **可持续性 / 可执行规模**：结合 cap/floor（M3）判断费率天花板，结合历史差价与费率分布判断稳定性，结合 OI/深度算出「进多少钱不会把机会打没」。

再加上两者都没有的：多列组合排序、筛选条件持久化、关注列表、导出。

### 7.2 一个统一的净收益模型

资金费 + 价差 + 借币利息 + 双边手续费 + 平台币抵扣 + 返佣（API 档）+ 滑点估计，全部进同一个公式，输出**一个数**。taoli 把这些散落在榜单、Fee 列、PnL 区、FAQ 四个地方；qqq.bot 干脆不算。这是我们最容易建立信任的地方——**用户不需要在四个地方心算**。

### 7.3 兑现架构红利，别背它的债

taoli 相当一部分复杂度是在偿还「跑在浏览器里」的债：解除 CORS（要装 `*://*/*` 权限的插件）、自建 `/proxy` 中转、Signer 把助记词挪出浏览器、VNC + Tailscale 做 7×24、`--user-data-dir` 多开、后台标签会被节流所以「不要关闭或最小化网页」。**Python + NiceGUI 一个都不用背。**

同时把它最弱的一环直接变成我们的卖点：**SQLite 持久化 + OS keyring / 主密码派生的真加密 + 定期备份 + 可迁移的配置包**。它的 P&L 存在一个随时会被浏览器清掉的 IndexedDB 里——跨所套利的对账数据积累几个月后价值极高，这个短板不可接受。

### 7.4 「看板 + 自动化」合体，但要有 kill switch

taoli 是手动挡，qqq.bot 是自动挡。我们做**带完整仪表盘的自动挡**：taoli 的执行原语（VA/VB、Sequence、Flat、四道闸门、价格安全区间）+ qqq.bot 的规则引擎和 ADL 响应 + 全套告警。
但要重视一个信号：**作者真实运营 1.5 年后仍然坚持「不能无人值守」**。跨所套利的单腿风险可能确实不适合完全无人值守——所以自动化必须配足够强的告警（M10）和随时可拉的总闸。

### 7.5 数据资产：时序自持

差价时序、费率时序、成交回执、ADL 快照——这些在浏览器里存不下，在我们这里是白菜价。有了时序才有：阈值的分布依据（M6）、机会的历史稳定性排序（7.1）、**回测**（两者都没有，而用户已有 `backtest_lab.py` 基建）。这是 taoli 结构上追不上的地方。

### 7.6 多账户做成一等公民

一份进程管 N 组 API Key，账户维度聚合持仓、敞口和 PnL，稳定 ID + 显示名分离。taoli 只有「命名实例 + 开多个浏览器」，1.5 年、5487 人群都没做批量编排——**这是个明确的空白市场**。

### 7.7 补上它外包出去的两块

**充提状态监控**（跨所搬砖的硬前置）和**收益计算器**——这两样 taoli 都靠第三方 bot 补的，说明需求真实存在而主产品没做。我们直接内建，别重复它「外包」的路径。

### 7.8 移动端只读监控

见 S14。仓位出问题的时候人往往不在电脑前，而它的官方答案是「远程桌面连上去」。

### 7.9 复用已有基建

微信推送通道（`crypto_social_tracker` 那套）直接接进 M10 的事件矩阵，通道数比 taoli 还全；Windows 服务器和 `5.78.104.216` 可以按 S13 的纪律部署（但注意它推荐东京，我们现有机器的地域要重新评估 ping）。

---

**一句话总结**：taoli.tools 的价值不在它有多少功能，而在它把**「两腿对冲下单」这一件事的失败模式全部标了出来并给了处理方案**——归一化口径、含挂单的平衡判据、陈旧度阈值、面值系数、补单的 PnL 归属。我们抄这些血泪教训（第 2、3 节），跳过它的架构代价（第 5 节），然后在它和 qqq.bot 共同的空白处——**扣费后的跨所配对净收益 + 可回测的时序数据 + 一等公民的多账户**——建立我们自己的东西。
