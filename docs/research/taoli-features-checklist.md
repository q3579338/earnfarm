# taoli.tools 功能点原始清单（99 条）


## MUST (36)

### 通知渠道矩阵（4 通道）

**是什么**: Settings 第一列的通知设置支持 4 种投递方式：Web（需授予网页通知权限）、TG（填 Bot Token，创建 Bot 后必须点一次 Start 才有权限推送）、Lark/飞书（填 Webhook URL）、Bark（填 Server URL）。没有邮件、没有通用 Webhook、没有微信。

**怎么实现**: TG 用 Bot Token + chat_id 发消息；Lark 走自定义机器人 Webhook URL；Bark 走 Server URL（iOS 推送）；Web 用浏览器 Notification API。文档明确提示 TG Bot 必须先被用户点 Start，否则无推送权限——这是实现时最容易踩的坑。

**判断**: qqq.bot 已知能力里完全没有告警层，这是纯增量。TG + 飞书 Webhook 是国内套利用户的最大公约数，实现成本极低（两个 HTTP POST）。用户本人已有微信推送基建（crypto_social_tracker），可以直接把微信当第五通道加上去，比 taoli 还全。

### 6 类告警事件 + 显式轮询周期

**是什么**: 六种可独立开关的通知类型：Order（工具内触发下单，注意不是成交）、Warn（现货余额不足 / 超过 MaxO、MinA、MaxA / A then B 模式下 A 出错）、Stale（价格已 5 分钟没更新，每 60 秒检测）、Error（每个 Pair 下方出现红字）、Risks（Risk 列出现红字，或勾选 FLAT 后两边不平衡，每 15 秒检测）、Price（价格超出设置的安全范围，每 30 秒检测）。

**怎么实现**: Stale=价格 5 分钟未更新、每 60s 检测；Risks=风险红字或 FLAT 不平衡、每 15s 检测；Price=超安全范围、每 30s 检测。Order/Warn/Error 是事件驱动而非轮询。

**判断**: 这是整份文档里最可直接落地的设计。事件分类的颗粒度经过 1.5 年真实运营打磨：把"下单"和"成交"分开、把"价格不动"（Stale，说明 WS 断了）单列一类、把"单腿/不平衡"（Risks）单列一类——正好覆盖跨所套利最致命的三种故障。轮询周期（60/15/30 秒）可以直接抄，省掉自己调参。

### 设置导出/导入（JSON + tt- 密钥串双因子）

**是什么**: Settings 里 Export 按钮下载一个 JSON 文件，同时把一个 `tt-` 开头的密钥字符串复制到剪贴板；Import 需要同时上传 JSON 并输入该密钥串。导出内容包含除 Token（登录态）和 P&L 之外的全部 Settings 页面内容，导入会覆盖当前设置。

**怎么实现**: 加密后的 JSON 文件 + 独立的 `tt-` 前缀密钥串（走剪贴板，不落文件）。明确排除登录 Token 和历史 P&L 数据。

**判断**: 文件与解密密钥分离投递，是备份含 API Key 配置的正确做法——文件泄露单独没用。我们的工具有本地数据库，更需要一个"能带走的配置包"来做换机/换服务器迁移。成本 30 行代码。

### 四类报表 × 三种投递方式

**是什么**: Settings 第三列专做导出：Trading（选定日期的总表 + 按 Pair 中 A 和 B 分别筛选的分表）、交易小票（点导出后先显示一张小票，SYMBOLS 和 EXCHANGES 默认隐藏可点开）、Funding（永续资金费，最近 7 天总表 + 按 Ticker 分表）、Lending（现货杠杆借贷利息，必须先选 Ticker）。每条记录三种导出选项：Webpage（浏览器里直接渲染 CSV）、Telegram（通过 Bot 把 CSV 文件发给你）、Download（下载 CSV）。

**怎么实现**: CSV 格式；Trading 按日期切；Funding 固定最近 7 天；Lending 强制先选 Ticker。三种投递复用同一份数据。

**判断**: qqq.bot 没有对账/报表层。这套设计的两个巧思值得抄：一是把 Funding 和 Lending 拆成独立账本（资金费套利的收益来源就是这两块，混在 PnL 里看不清），二是 Telegram 投递——服务器上跑的实例不用远程桌面就能把报表拿到手机上，运维体验碾压"去服务器上下载文件"。

### Risks 三指标风控面板（ADL / MR / Liq Price）

**是什么**: 交易页每条腿的 Risks 列展示三种风险信息，按顺序显示、放不下就显示省略号，用红/黄/绿/灰四色分危险等级：(1) ADL 自动减仓优先级，五个等级，支持的交易所仅 Binance、Bitget、Bybit、Gate、OKX；(2) MR 保证金率，大于 100 时不显示，统一采用币安口径「权益/保证金」即数字越大越安全，工具只拿交易所返回值做简单后处理（通常取一次倒数）；(3) Liq Price 清算价，以 $ 开头。按 Shift 可切换为 Average 持仓均价。

**怎么实现**: 爆仓价百分比 = `市价 = (买一价 + 卖一价) / 2`，然后 `爆仓价百分比 = 爆仓价 > 市价 ? 爆仓价 / 市价 : 市价 / 爆仓价`。MR 统一取倒数归一到「权益/保证金」。文档诚实说明：不同交易所提供的风险信息种类不同，有数据就显示，没数据不显示，但不代表没风险。

**判断**: qqq.bot 是"ADL 后自动降 target"（事后补救），taoli 是"事前可视化"。两者应该并存。最值得抄的是 **MR 归一化**：六家交易所的保证金率定义和方向都不一样（有的越大越危险），统一到币安口径是必须做的脏活，taoli 已经把答案给了。ADL 只有 5 家有数据这条信息也很有用，省得我们为 HTX 白折腾。

### 报价陈旧度三色标记（3s / 9s）

**是什么**: Best Bid and Ask 正常显示灰色；如果价格已是 3 秒前更新则显示黄色；已是 9 秒前更新则显示红色。旁边有 `⟳` 强制刷新价格按钮。另有独立的 `Price expired` 错误（报价超过 3 秒未更新）。Persistent 的 Stale 通知则是 5 分钟阈值。

**怎么实现**: 3 秒变黄、9 秒变红、5 分钟触发 Stale 通知（每 60s 检测）。每条腿的 Position 和价格都各带一个 `⟳` 强制刷新按钮。

**判断**: 跨所套利最隐蔽的杀手就是"一边 WS 断了但价格还挂在屏幕上"，导致按陈旧价格算出的假价差下单。三色 + 强制刷新按钮 + 5 分钟告警是三层防御，成本几乎为零。我们的 500ms 收敛循环如果拿着 9 秒前的价格跑，就是在按错的价差反复下单。

### API Key 权限配置的逐所 runbook

**是什么**: 通用铁律写在两处：「建议开启 API Key 的 IP 白名单功能」+「一定**不要**开启 API Key 的转账和提现功能」（DANGER 级）。逐所差异：Binance——必须先填「只访问受信任的 IP」或取消勾选「默认安全限制」才能勾权限，且**经典账户和统一账户权限勾选不同**，更改账户类型后必须重建 API Key；OKX——只勾「读取」和「交易」，账户模式需切到合约模式/跨币种保证金/组合保证金，永续只支持全仓；HTX——勾「读取」和「交易」；Gate——必须先升级统一账户，跨币种或组合保证金；Bybit——选「读写权限」并勾统一交易账户中的全部四个选项；Bitget——USDC 合约和 U 本位合约要分别设置持仓模式。**六家全部要求「单向持仓」**。

**怎么实现**: 六家统一要求：单向持仓 + 读取/交易权限 + 禁止提现转账 + 建议 IP 白名单。Bybit 需要「读写权限」+ UTA 四项全勾。Gate/Bitget 的市价买现货传入的是 U 的数量而非币的数量，会导致实际成交量与设置 Size 有出入。

**判断**: 这是 1.5 年踩坑攒出来的配置清单，直接抄进我们的引导流程能省掉海量客服。最关键的两条：(1) 六家统统要求单向持仓——我们的工具应该在保存 API Key 时就自动检测持仓模式并报错，而不是等下单失败；(2) 币安改账户类型后 API Key 失效必须重建——这是个纯坑，只有踩过才知道。

### 资金费率周期归一化（8H ↔ 1Y 切换）

**是什么**: 榜单的资金费率列本身是一个可点击切换的周期基准。同一列可显示「8H 资金费率」或「1Y 资金费率」，我在浏览器里实测到表头在两者间切换。配合「间隔」列（各币种结算周期 1H/4H/8H 不同），把不同结算频率的币拉到同一把尺子上比。

**怎么实现**: 表头列 = 交易所 | 未平仓额 | 日成交额 | ↓8H/1Y 资金费率 | 下次资金费率 | 上限/下限 | 间隔。每列可排序（─ 未排序 / ↓ 降序）。间隔数据来自各所合约接口，Binance 走 fapi.binance.com/fapi/v1/fundingInfo。

**判断**: must — 这是 qqq.bot 榜单最大的硬伤（原始 funding-spread 不年化）。1H 结算的 0.01% 和 8H 结算的 0.05%，不归一化根本没法比，用户会系统性选错币。实现成本极低（一个乘法 + 一个下拉），收益最大。

### 资金费率上限/下限（fundingInfo）

**是什么**: 榜单单列显示每个永续合约的资金费率封顶值和封底值。交易页面里按 Shift 也能在 Fee 栏看到该合约的资金费率上下限。

**怎么实现**: Binance 用 fapi.binance.com/fapi/v1/fundingInfo（返回 adjustedFundingRateCap / adjustedFundingRateFloor / fundingIntervalHours）。其余所类似。

**判断**: must — 决定一个高费率机会的「天花板在哪」。很多小币 cap 只有 ±0.5%/8h，而某些币 cap 高达 ±2%，同样是当前 0.3% 的费率，风险和可持续性完全不同。qqq.bot 完全没有这个维度。六家 CEX 都有对应接口，成本很低。

### VA / VB —— 每腿独立价距，与目标差价解耦

**是什么**: 勾选 Limit 后启用。VA、VB 分别是 A 腿、B 腿的委托价相对买一/卖一价的偏移，单位百分比。V<0 = 超价吃单（快但可能亏），V=0 = 贴买一卖一挂单，V>0 = 通常不立即成交（做 maker 赚返佣）。留空该腿走市价单。

**怎么实现**: 文档给了可直接验算的算术：「差价设 0.5%，VA -0.1%，VB -0.2% → 除去手续费最少赚 0.2%」；「VA +0.1%，VB +0.2% → 最少赚 0.8%」。超出交易所限价范围时输入框变红但仍可尝试下单。

**判断**: must — 这是全文档最有价值的一个设计。它把「我要多大的差价才动手（目标）」和「我下单有多激进（执行）」拆成两个正交旋钮，还能一腿吃单一腿挂单（贵的所吃单、便宜的所挂单赚 maker）。qqq.bot 只有 FOK 限价单，没有任何等价表达能力。而且这个 V 值直接决定了保底利润的下界，是可计算、可回测的。

### 单腿救援：市价追单 + 市价补单，且计入 PnL

**是什么**: 两个独立机制。(1) 追单：未成交挂单列表里按住修饰键，取消按钮变成 ✓ 市价追单。(2) 补单：红色错误信息行按住修饰键出现 ✓，后面直接跟着「需要补的方向 + size」，点击市价补上。关键是——两者在工具内操作成功后都能正确计入对应的 PnL。

**怎么实现**: 追单实现有坑：部分交易所没有改单接口，实现方式是「先取消再重新下单」，因此可能出现取消了但没重下的情况；且无二次确认，可能要点多次。

**判断**: must — 单腿是这类工具唯一真正会亏钱的失败模式。qqq.bot 靠 500ms 收敛循环自动补，但收敛循环搞不定的残局（API 假成功、网络断连）就没有出口了。给用户一个「一键把这条腿补平，并且账目自动对上」的按钮，是把不可控风险变成可控操作的关键。PnL 归属这一点尤其重要，否则用户补完仓账就乱了。

### Flat 持仓平衡预检

**是什么**: 每个交易对可勾选 Flat。勾选后每次双边下单前检测两腿持仓是否平衡：若 |A持仓| 与 |B持仓| 之差 ≥ Size，则黄字警告、不下单，但不中断 Loop。

**怎么实现**: 文档给了判平衡的严格口径：「Position + 所有未成交订单总量，AB 两边加起来是否等于 0」——即未成交挂单必须计入，不能只看已成交持仓。

**判断**: must — 防止在已经单腿的状态下继续叠加，把小错滚成大错。那个「未成交挂单也要计入」的口径是血泪教训，我们直接抄，能省一轮线上事故。

### MinA/MaxA（币本位）+ $MinA/$MaxA（U 本位）双轨仓位上限

**是什么**: 四个仓位边界。MinA/MaxA 以币计，$MinA/$MaxA 以 U 计，按住修饰键才显示后者。两套同时填写时是 AND 关系，都生效。只约束 A 腿，不约束 B。触发时黄字报错并暂停下单，但不停止 Loop。

**怎么实现**: 黄色未成交挂单也计入仓位。文档诚实承认「可能因请求延迟或持仓未及时更新导致超出一两单」。现货时 MinA 只能填 ≥0。

**判断**: must — 币本位和 U 本位两把尺子必须都有：币本位管「我要建多少仓」，U 本位管「我最多押多少钱」，币价暴涨暴跌时两者会严重背离。qqq.bot 只有单向棘轮式 target，表达不了「区间」。另外「触发时暂停但不停 Loop」的语义很重要——价格回来了能自动恢复，不用人工重启。

### 未平仓额 / 日成交额 过滤器

**是什么**: 榜单顶部三个可调过滤器：未平仓额>=$1M、日成交额>=$1M、间隔=*H，外加 22 家交易所的多选开关行。

**怎么实现**: OI 数据源：OKX /api/v5/public/open-interest?instType=SWAP、Backpack /api/v1/openInterest、以及它自建的 taoli.tools/binance-open-interests 缓存端点。成交额走各所 24hr ticker（如 fapi.binance.com/fapi/v1/ticker/24hr）。

**判断**: must — 极低成本、极高收益。资金费率榜单不加流动性过滤就是垃圾场：费率最高的永远是没人交易的空气币，进去就是滑点和无法平仓。qqq.bot 的榜单没有任何流动性维度。这个必须做，而且应该是默认开启。

### 差价计算公式（中点归一化）与历史差价 K 线

**是什么**: 明确写出两个方向的差价公式，并且点击方向标签可打开该方向的历史差价图表，左上角可选蜡烛宽度单位、以及按 OHLC 中哪个字段计算差价。

**怎么实现**: -A+B：(A_Bid1 - B_Ask1) * 2 / (A_Bid1 + B_Ask1) × 100；+A-B：(B_Bid1 - A_Ask1) * 2 / (B_Bid1 + A_Ask1) × 100。注意分母是**两者之和**即中点的 2 倍，属于中点归一化，不是「以 A 为基准的比率」。

**判断**: must — 公式本身要抄（中点归一化在双边都动的时候比单边基准更对称、更稳）。历史差价 K 线是定阈值的唯一理性依据：不看分布就拍脑袋设 0.5%，要么永不触发要么天天亏。qqq.bot 只有 latest-spread 快照，没有分布。我们有 Python 后端，存差价时序比它在浏览器里存容易得多。

### N —— 合约乘数换算系数

**是什么**: 添加交易对时的一个参数：N 表示一个单位的 A 等于多少个单位的 B。绝大多数情况填 1。

**怎么实现**: 文档举例：A 是 1MCHEEMS，B 是 1000CHEEMS，A = 1000 × B，所以 N 填 1000。复制交易对并交换 A/B 时，N 自动取倒数。

**判断**: must — 看着琐碎，但 1000PEPE / 1MPEPE / PEPE 这类不同面值命名在六家 CEX 之间极其常见，搞错就是 1000 倍的仓位错配，一次就爆。必须在建对时显式建模，不能靠 symbol 字符串猜。

### 价格陈旧度分级 + 硬阻断

**是什么**: 买一卖一价按新鲜度着色：灰色正常，黄色表示已是 3 秒前的数据，红色表示已是 9 秒前的数据。超过 3 秒未更新直接报 Price expired 并阻止下单。每腿另有 ⟳ 强制刷新价格 / 强制刷新持仓的按钮。

**怎么实现**: 陈旧原因文档列了三种：网络断开/延迟过高、订单簿交易太少导致价格本来就不动、本机时间太快。另有独立的 Stale 通知类型（5 分钟没更新，每 60 秒检测）。

**判断**: must — 拿过期报价算出来的差价是幻觉，照着下单必亏。成本几乎为零（一个时间戳比较 + 三档颜色），但能挡掉一整类事故。特别是 HTX/Gate 的冷门币，订单簿几分钟不动是常态。

### 资金费率筛选器（首页 = 机会发现主入口）

**是什么**: https://taoli.tools/ 首页就是一张 22 家交易所的永续资金费率总表。实测列头：交易所 | 币种(表头内嵌搜索框) | 未平仓额 | 日成交额 | 资金费率 | 下次资金费率 | 上限/下限 | 间隔。未平仓额/日成交额/资金费率/下次资金费率四列可点排序，默认按资金费率降序（↓）。覆盖 Binance/Coinbase/Bybit/OKX/Bitget/Gate/HTX/Kraken/KuCoin/MEXC/Backpack/Hyperliquid/Lighter/Aster/Grvt/Ethereal/Paradex/Pacifica/Extended/StandX/ApeX Omni/Ondo Perps。

**怎么实现**: 数据经自家 /proxy?url= 服务端 CORS 代理拉各家公开行情（实测抓到 gate futures contracts+tickers、coinbase products、kraken tickers+instruments、backpack markets/markPrices/tickers/openInterest、binance-open-interests、binance leverage brackets、ondo markets、grvt/stand-x/apex-omni tickers）。表格用 react-virtuoso 虚拟列表渲染。

**判断**: 这是 qqq.bot 最大的短板对照组：qqq.bot 的 funding-spread 只给原始数值，而前作把"机会发现"做成了独立的、无需 API Key 就能看的公开页面——既是获客漏斗（免费看榜 → 点"开始交易→"进 /trade），也是真正能用的筛选器。我们的 NiceGUI 工具应该有同构的一页。

### 资金费率 8H⇄1Y 年化切换 + 结算间隔归一化

**是什么**: 资金费率列头旁有一个独立按钮在 `8H` 和 `1Y` 之间切换（实测点击循环：8H→1Y→8H→1Y）。8H 是把各家不同结算周期的费率折算到统一的 8 小时口径，1Y 是年化。另有独立的"间隔"列显示该合约的结算周期，以及"间隔=*H"滑块直接按结算周期筛选。

**怎么实现**: 程序内部枚举了完整的 ISO8601 周期常量：PT5M、PT15M、PT30M、PT1H、PT2H、PT4H、PT8H、PT12H、PT24H（另有 P7D、P30D）。年化 = 单期费率 × (365×24小时 / 间隔小时数)。

**判断**: 六家所里 Binance 主力 8h 但热门币 4h/1h、Bybit/OKX/Bitget 混用 8h/4h/1h、Gate 部分 1h——不归一化的话 0.05% 的 1h 费率和 0.05% 的 8h 费率会被排在同一行，这是我们必须避免的错。qqq.bot 的 funding-spread 恰恰就是不年化不归一化。公式简单，收益极大，第一优先级实现。

### 资金费率上限/下限（cap/floor）列

**是什么**: 表格有独立的"上限 / 下限"列，展示该合约资金费率的交易所硬性上下限。交易页面里按住 Shift 点 Fee 也能看到"资金费率上下限"。

**怎么实现**: 代码里可见 `fundingRateUpper`、`adjustedFundingRateFloor` 字段，渲染时 ×100 保留 3 位小数。数据来自各所合约信息接口。

**判断**: 这是判断"极端费率能不能持续"的一票否决位。看到 -2% 的资金费很兴奋，但如果该合约 floor 就是 -0.75%，那个 -2% 要么是数据错要么马上会被夹回去，年化外推完全失真。qqq.bot 没有这一列。实现成本约等于零（合约信息接口一次性拉），信息价值很高。

### 未平仓额 + 日成交额 双滑块容量过滤

**是什么**: 顶栏两个 range 滑块："未平仓额>=$1M"、"日成交额>=$1M"，默认都是 $1M。先过滤再排序。第三个滑块"间隔=*H"按资金费结算周期过滤。

**怎么实现**: OI 数据各所单独抓（binance-open-interests 是自家聚合端点、backpack openInterest、aster-open-interests 等）；成交额取 24h quote volume。

**判断**: 资金费年化榜的头部永远是垃圾小币——年化 300% 但 OI 只有 20 万刀，进 5 万刀就把费率打回去了，还可能被拉盘爆空单。先用容量闸门砍掉不可执行的行，再谈排序，这是让榜单从"好看"变成"能下单"的关键一步。滑块比固定阈值好，因为不同资金量的人容量线不同。

### 手续费门槛公式（写进 FAQ 的可执行判据）

**是什么**: FAQ 第 1 条给出双向套利的盈亏平衡公式：两个方向（-A+B 和 +A-B）的预设差价数字之和 ≥ 两边手续费之和的 2 倍。原文例子：A 手续费 0.1%、B 手续费 0.05%，则两个差价之和要 ≥ 0.3%。

**怎么实现**: 2×(feeA+feeB)。系数 2 来自一个完整往返要在 A、B 两边各吃两次手续费（开+平）。允许其中一个方向填负数（愿意亏差价平仓），只要两数之和过线。

**判断**: qqq.bot 的机会榜完全不扣手续费，这是它最大的谎报来源。前作虽然也没在榜单里自动扣（它把这事留给用户），但至少把公式写死在文档里了。我们应该更进一步：直接在榜单里算净值——用用户实际 VIP 等级的 maker/taker 费率，输出"扣费后年化"，并把这条 2×(feeA+feeB) 作为红线在 UI 上标出来。

### VA/VB 价距 → 实得差价的线性公式

**是什么**: 限价模式下 VA、VB 是 A/B 两腿委托价相对买一卖一价的偏移量（百分比）。V<0 超价吃单（快但亏），V=0 挂买一卖一，V>0 通常不立即成交。

**怎么实现**: 实得差价 = 预设差价 + VA + VB。文档两个例子：差价 0.5%、VA=-0.1%、VB=-0.2% → 除手续费外至少赚 0.2%；差价 0.5%、VA=+0.1%、VB=+0.2% → 至少赚 0.8%。输入超出该交易对限价范围时输入框变红。

**判断**: 这是把"挂单还是吃单"变成一个可量化滑杆的做法：用户直接看到"我多挂 0.1% 能多赚 0.1%，代价是成交概率下降"。qqq.bot 的 FOK 限价单只有单一超价参数，没有把两腿分开、也没把净收益公式暴露出来。我们两腿分别给 V 参数 + 实时显示预期净收益，是低成本高体感的改进。

### 价格陈旧度三色 + Stale 通知

**是什么**: 买一卖一价正常灰色；黄色 = 该价格已是 3 秒前的；红色 = 已是 9 秒前的。另有 Price expired 报错（>3 秒未更新则拒绝下单）。通知类型里 Stale = 价格 5 分钟没更新（每 60 秒检测一次）。每腿价格旁有 ⟳ 强制刷新按钮。

**怎么实现**: 3s / 9s 两档阈值；单边价格过期不影响另一边的单边下单。

**判断**: 跨所套利最致命的失败模式是拿着一个所的陈旧价去和另一个所的实时价算差价，算出一个不存在的机会然后单腿。三色 + 硬性拒单是极低成本的保险。qqq.bot 的 500ms 收敛循环里没看到对行情时效性的显式门禁。这条必须做，而且阈值（3s/9s）可以直接沿用。

### 机会列表的列与排序（含 8H↔1Y 年化切换）

**是什么**: 表头七列：Exchange(交易所，点击跳该所返佣注册链接) / Symbol(表头本身就是搜索框) / $OI(未平仓额) / 24H $Vol(日成交额) / Funding(资金费率) / Next Funding(下次结算倒计时+预测费率) / Upper/Lower(费率上下限) / Inter(结算间隔)。前四个可排序（↓/↑/─ 三态字符），默认按 funding 降序。Funding 列旁有个 `8H`/`1Y` 小按钮切换显示口径。行点击选中变黄并唤出右侧详情面板。币种单元格显示 BASE/QUOTE，已下架后缀 ` !`，异常状态（盘前盘后/只减仓）后缀 ` ?`。

**怎么实现**: 排序 key 分别是 openInterest / quoteVolume24H / fundingRate8H / nextFundingRate，单列排序，方向 asc↔desc 互切。8H 显示 `(fundingRate8H*100).toFixed(3)%`，1Y 显示 `(fundingRate8H*100*3*365).toFixed(1)%`——朴素年化，不复利、不扣手续费。倒计时用相对时间函数，到点显示 i18n 的 `just_now`/`刚刚`。

**判断**: 列的选择本身值得抄（OI 和 24h 量是过滤貔貅/流动性陷阱的最低成本指标，qqq.bot 完全没有）；但 1Y 的算法是反面教材：我们必须做「扣双边手续费后的净年化」和「跨所净费差」，否则和它一样只是把原始数字乘个 1095。

### 三个对数滑块做阈值过滤（OI / 24h量 / 结算间隔）

**是什么**: 页面顶栏三个 range 滑块，不是输入框：`open_interest >= $X`、`vol_24h >= $X`、`interval = *H`。拖动即时过滤下面的表。

**怎么实现**: OI 和 Vol 滑块 min=2 max=10 step=1，值 = 10^n，即 $100 → $10,000,000,000，默认 1e6($1M)，label 里用人类可读缩写显示。间隔滑块 min=-1 max=3 step=1，值 = 2^n → 0.5/1/2/4/8，其中 0.5 渲染成 `*` 表示不限，默认 `*H`。

**判断**: 用对数滑块代替数字输入框，是把「几个数量级」这种模糊意图变成一次拖动，比让用户敲 1000000 好太多，而且天然防手滑多打一个零。NiceGUI 有 ui.slider，实现成本极低。这是本次挖到最实用的交互巧思之一。

### 主面板五列指标（Position / Fee / Bid-Ask / Available / Risks）

**是什么**: trade 页每个 Pair 占两行（A 一行 B 一行），每行固定五个字段：持仓量、费用（永续=下次资金费时间+费率；现货杠杆=每小时利息）、买一/卖一价、可用资金、风险指数。列头 Position / Fee cost / Last 本身就是「点击强制刷新」按钮（写作 `Position ⟳`）。均价列只在 ≥2xl 宽屏显示。右上角显示 `Pair Count: N` 和 `Settings ↓`。

**怎么实现**: 价格陈旧用颜色分级：>3 秒黄色，>9 秒红色（f===1/f===2）。Risks 列按顺序拼三段：ADL 五档用字符 ┋ ┇ ╏ ▪ ▫（左→右被 ADL 概率递减）、MR 保证金率（>100 不显示，数值越大越安全）、Liq Price 爆仓价；每段按危险度着色 红/黄/绿/灰，MR 阈值 >5 灰、>2 绿、>1.5 黄、否则红；爆仓价危险度 = max(爆仓价/市价, 市价/爆仓价) 走同一套阈值。

**判断**: 这是整个产品最值得抄的一屏。五个字段就是对冲套利真正要盯的全部；用「列头即刷新按钮」省掉一排工具按钮；用颜色而不是弹窗表达价格陈旧。ADL 用五个 Unicode 方块表达等级，比进度条更省空间。我们六家所里 Binance/Bitget/Bybit/Gate/OKX 都能拿到 ADL，可以照搬。

### 创建一个对冲任务的流程（底部单栏，4 步）

**是什么**: 永远固定在页面最底部的一条添加栏，不是弹窗、不是向导：① ⟳ 刷新 ② 「Symbol, CA」搜索框（可粘合约地址加自定义链上代币；末尾加 `/` 切精确匹配显示全部，否则模糊匹配最多 50 条） ③ A: 下拉 和 B: 下拉（按 spot→isolated→cross→perp 排序，按交易所账户名分组） ④ Add Pair。勾 Advanced 会在上方多出一整行预设参数：N（A 与 B 的面值倍数，1000CHEEMS vs 1MCHEEMS 填 1000）、Sequence、Flat、Limit、MaxO/VA/VB、Size、MinA/MaxA/$MinA/$MaxA、-A+B 和 +A-B 的预设差价 + 初始状态（Stop/Once/Loop），点 Add Pair 后可自动开跑。

**怎么实现**: 添加即 IndexedDB 事务写 pairs/pairConfigs/pairStates 三张表，没有服务端。未配置任何交易所时整条栏替换为一句 `Go to Settings to add Exchange, Chain and Token ->`。

**判断**: 「创建任务 = 一条常驻底栏」比模态向导更适合需要反复开仓的场景，而且 Advanced 折叠把 13 个参数藏起来但保留一键复用。我们的 NiceGUI 版本应该照这个思路：默认 3 个控件，高级参数折叠。

### 可粘贴的「交易对配方字符串」自动填充 A/B

**是什么**: 在搜索框里粘贴形如 `BN-P:BTC/USDT+OK-S:BTC/USDT` 的字符串（两位交易所代码-一位类型代码:BASE/QUOTE，两腿用 + 连接），会自动解析并同时选中 A 和 B 两个下拉，无需手动搜两次。

**怎么实现**: 正则 `^\s*([A-Za-z]{2})-([A-Za-z]):([^/+\s]+)/([^/+\s]+)\s*$` 逐腿解析，两位码查交易所枚举，一位码查 spot/isolated/cross/perp 枚举；解析成功后在当前 tickers 里精确匹配并自动挑一个已配置的账户。

**判断**: 这是 TG 群运营的隐藏基础设施——群友可以直接贴一行文本互相分享机会，对方粘贴即建仓。我们如果也要做社群/信号分发，这是成本极低、价值极高的一环，比截图分享强得多。qqq.bot 没有。

### 差价图：三窗格 Lightweight Charts + 资金费竖线标注

**是什么**: 点 Pair 里的 `-A+B:` 或 `+A-B:` 标签，弹出一个浮动 dialog（最小宽 1016px，高度半屏，按你点击位置决定贴顶还是贴底，左边距会随侧栏是否展开自适应）。窗格0：主差价基线图（>0 绿填充、<0 红填充，格式 `x.xx%`），叠加 A、B 各自的溢价指数虚线（蓝/橙）；窗格1：A、B 双腿 K 线（蓝/橙，B 按 N 缩放）+ 指数价 K 线（透明实体、只画边框，价格后缀 ` I`）；窗格2：成交量柱状图，A 向上 B 向下镜像。顶栏是 K 线周期下拉 + `-A: <ticker>`(蓝) `+B: <ticker>`(橙) + ⨯。

**怎么实现**: 差价公式 (a-b)*200/(a+b)。周期下拉取 A 和 B 两家所支持周期的交集，默认 60 秒，每 2 秒刷新。资金费结算点用自定义 canvas primitive 画成半透明竖线 + `+0.0100%` 文字标签，同一横坐标的标签自动上下堆叠 13px 防重叠；周期 >8 小时（480 分钟）时自动隐藏这些标注。十字光标默认磁吸，按修饰键变自由。

**判断**: 「把资金费结算时刻画成竖线叠在差价图上」是这个产品最强的一个可视化：一眼看出差价的周期性是不是被资金费驱动的。三窗格分工（差价/价格/量）也是对的。我们即使不用 Lightweight Charts（Python 侧可用 echarts/plotly），这个图层设计值得原样搬。

### Pair 卡片的六个字符按钮（删除/复制/最小化/上移/镜像/下移）

**是什么**: 每个 Pair 右上角三个字符按钮，默认态是 ⨯(删除，只从页面消失不动实际持仓) / ◫(原样复制一份) / -(最小化)；按住修饰键变成 ↑(上移，右键=置顶) / ◧(镜像复制：A B 互换、N 取倒数、MinA/MaxA 对调、Sequence AB↔BA、预设差价互换、min/maxU 取负) / ↓(下移，右键=置底)。运行中(Once/Loop 等待下单)时禁止移动。最小化后收成一行摘要：A 和 B 的名称、持仓量、未成交挂单量(黄色)、费率、风险，末尾一个 ○/◉ 表示是否有活动。

**怎么实现**: 排序靠 IndexedDB 里的 ts 字段，上移就把 ts 改成上一条的 ts-1，置顶就改成全表最小 ts-1。

**判断**: 「镜像复制」是套利工具的杀手级细节——开完 -A+B 想准备反向平仓单，一键就能生成一个所有参数都正确取反的对照 Pair。我们必须有这个。最小化行的摘要字段选择（持仓/挂单/费率/风险/活动指示灯）也可直接照抄。

### 未成交挂单的行内展示与操作

**是什么**: 交易对名称后面用黄字紧跟挂单信息：先是 `订单数∑总量`（不同方向互相抵消），然后逐条列出每个委托 `委托总量(已成交量)$价格 ⨯`。⨯ 取消无二次确认；按修饰键后 ⨯ 变成 ✓ 市价追单（部分交易所无改单接口，实现是先撤后下，可能出现撤了没下的情况）。判断 AB 是否平衡的口径明确写在文档里：Position + 所有未成交订单总量，两边加起来是否为 0。

**怎么实现**: 每秒轮询 getOrders 并做 JSON 深比较避免无谓重渲染。

**判断**: 把挂单塞进标题行而不是单开一个订单表，是密度取舍的典范；`∑` 抵消汇总直接回答了「我现在到底偏了多少」。那个平衡口径（含挂单）是对冲工具的正确定义，我们要照抄。但「无二次确认 + 撤了可能没下」是明确短板，我们的追单要做成幂等重试而不是撤了再下。

### 三级消息行（灰/黄/红）+ 一键补单

**是什么**: 每个 Pair 下方有一行状态消息：灰色=可忽略的 info、黄色=需留意但无大碍的 warn（不会中断 Loop）、红色=至少一边失败的 error（会停止运行、仓位单腿）。重要消息覆盖不重要的，刷新页面后仍在（持久化），点末尾 ⨯ 关闭。红色消息按修饰键会出现 ✓ 加上可重试的方向和 size，点一下市价补单，且补单的 PnL 能正确计入。

**怎么实现**: 存在 IndexedDB 的 pairStates 表里 lastError/lastWarn/lastInfo 三个字段，每条带 ts 和完整的 {ticker, side, size} 上下文，所以才能一键重放。

**判断**: 错误对象里存下足够重放的上下文，是把「报错」变成「可操作」的关键设计，成本极低价值极高。三色分级 + 覆盖策略也比堆一个日志列表好。这是我们的错误处理应该直接采用的模型。

### 下单按钮的状态化（Once/Loop 按钮即状态机）

**是什么**: 每个方向一行：`-A+B:` 标签(点击唤出差价图，两个字母各自在有挂单时变黄) + 实时差价% + 预设差价输入框(%) + 两个按钮。按钮不是「执行」而是三态开关：Once 未运行时显示 Once、点击后变成 Stop 并高亮（等待差价满足）；Loop 同理。两个按钮互斥禁用。按住修饰键时这两个按钮变成 `-A` 和 `+B` 两个单边下单按钮（红/绿底色），忽略差价直接下单。

**怎么实现**: 运行中会禁用该方向的预设差价输入和 Sequence/Flat/Limit 复选框，防止跑着改参数。

**判断**: 「按钮文字在 Once↔Stop 之间切换」比另加一个停止按钮省一半空间，且状态一目了然。单边下单藏在修饰键层也是对的——这是最危险的操作。我们的 NiceGUI 按钮应该采用同样的状态化写法。

### （短板）机会榜缺失的能力

**是什么**: 资金费首页只有单腿的原始费率，没有任何跨所配对：没有「同币种在 A 所做多、B 所做空的净费差」列、没有扣手续费/滑点的净年化、没有历史稳定性/波动率指标、没有借贷利率（现货杠杆腿的成本）并入计算、没有多列组合排序、没有保存筛选条件、没有收藏/关注列表、没有导出。1Y 只是 8h 费率 ×3×365。

**怎么实现**: 排序只支持单列；筛选状态不持久化（只有 8H/1Y 这个开关持久化）。

**判断**: 这正好是我们的机会窗口。作者用 1.5 年验证了「资金费榜」这个入口有需求，但把最难也最值钱的那一步（配对 + 净收益）留给用户心算。我们的机会榜必须默认就是「跨所配对 + 扣费净年化 + 历史稳定性」三列起步，否则没有差异化。

### （短板）参数输入区零引导

**是什么**: 下单区 13 个参数（Size / MinA / MaxA / $MinA / $MaxA / MaxO / VA / VB / N / 两个预设差价）全是裸 number input，只有 placeholder 是缩写。单位靠上标符号区分（A̳ A̿ U̳ U̿）。唯一的辅助是：聚焦 Size/MinA/MaxA 时会浮出一个小气泡显示按当前中间价折算的 U 金额。VA/VB 超出交易所允许范围时输入框变红，但仍可能允许下单。

**怎么实现**: 气泡取 A 的买卖一价和 B 的买卖一价×N 共 4 个数求平均作为估值基准。

**判断**: 这是它劝退新手的主因，文档 FAQ 有一半在解释这些参数。我们做 NiceGUI 版本时应该反过来：每个参数带一句 inline 说明 + 单位切换按钮而不是上标符号 + 实时展示「按当前差价，这一单预计净赚 X USDT（已扣双边手续费）」。


## SHOULD (42)

### 仓位限制护栏 MinA/MaxA + $MinA/$MaxA

**是什么**: Size 是单次下单量（币）。MinA/MaxA 限制 A 腿的最小/最大持仓量（币），按 Shift 后切换出 $MinA/$MaxA 限制持仓价值（U）。两组同时填写时是 and 关系，都生效。触发时暂停下单并显示黄字（如 `A: Position will be greater than MaxA`），但**不会停止 Loop**。只限制 A 不限制 B，黄色的未成交挂单也算在内。文档承认可能因请求延迟或持仓未及时更新导致超出一两单。

**怎么实现**: MinA/MaxA（币）与 $MinA/$MaxA（U）以 and 关系联合生效；未成交挂单计入；触发只暂停不中断 Loop；只作用于 A 腿。

**判断**: "币本位 + U 本位双重上限、and 关系"这个设计很实用：币价大涨时币本位上限还没到但 U 敞口已经超了。更重要的是**触发后只暂停不停 Loop**——这个语义选择是对的，价格回来了自动恢复，不需要人工重启。qqq.bot 的棘轮式 target 调整解决的是同类问题但更粗糙。

### FLAT 持仓平衡预检 + MaxO 挂单上限

**是什么**: FLAT 勾选后，该 Pair 每次双边下单前检测持仓是否平衡：如果 A 和 B 持仓绝对值相差超过或等于 Size，出黄字警告、不下单、也不中断 Loop。MaxO 是单边未成交的最大挂单数量（单位是订单），不填=无限制，文档承认可能因下单延迟或未成交订单未及时更新而超出。判断平衡的官方标准：Position + 所有未成交订单总量，A B 两边加起来是否等于 0。

**怎么实现**: 预检条件 `abs(|PosA| - |PosB|) >= Size` 则阻断；平衡判据 `PosA + 未成交A + PosB + 未成交B == 0`。

**判断**: FLAT 是防止"单腿累积"的最后一道闸——单腿是这类工具唯一真正致命的故障。"Position + 未成交订单"这个平衡判据要抄，只看 Position 会在挂单模式下误判。MaxO 防止限价单堆积成一堵墙。

### 多交易所实例（Unique Name）而非多账户管理

**是什么**: 添加交易所的方式是：在 Unique Name 输入自定义名字 + 下拉框选交易所 + 点 Add。可添加任意多个实例，同一交易所可加多次（等于多 API Key / 多账户）。保存后绿字显示资金量=成功，红字=配置有误且**不会保存**。点已添加交易所的名字可重命名，但"重命名可能会导致已有的 Pair 和 P&L 出错"。每个交易所有 `⟳` 按钮测 ping，官方建议不超过 150ms。VIP 页面注明「相同的交易所账户或钱包添加多次，资金量不会重复计算」。

**怎么实现**: Unique Name + 交易所枚举 → 实例；保存即验证（绿字显示资金量 / 红字拒绝保存）；`⟳` 测延迟，阈值 150ms；重命名会破坏已有 Pair 与 P&L 的引用关系（说明内部用名字而非 ID 做主键，这是个 bug-prone 的设计，我们应该用稳定 ID）。

**判断**: 这是我们要注意的**反面参考**：taoli 只有"命名实例"，**没有账户分组、没有批量操作、没有跨账户聚合视图**。1.5 年、5487 人群、付费 VIP 都没做这些，说明真实需求可能没想象中大——但也可能正是它的短板。我们做六家所的工具，至少应该有一个"全账户总览"（总权益、总敞口、各所可用余额），这是低成本差异化点。另外"配置错误就拒绝保存"和"ping 测试"两个小交互要抄。

### 诚实的威胁模型（风险提示页）

**是什么**: 明确列出安全边界：所有数据存在本机浏览器，API Key/Secret 只有「一层简单的加密」；恶意浏览器插件或木马可以偷走密钥；「建议限制 IP 白名单，但如果黑客控制了你的电脑，IP 白名单也无法保护你」；源代码遭供应链攻击密钥也会被偷；云服务器被黑同样被偷；**「如果 API Key/Secret 被盗，即使开启了 IP 白名单，即使没有转账提现权限，黑客仍然可以通过小币种对敲的方式转移资金。可以通过币种白名单模式限制一下，但用处不大，而且很不方便」**。金融风险侧还点名：单边成交需手动去交易所摆平、爆仓需手动追保、可能触发 ADL、系统假设 1 USD = 1 USD*稳定币（脱锚时假设破裂）。

**怎么实现**: 文案层面的能力，无需实现。但"币种白名单"作为对敲防御手段值得在 API Key 引导里提一句。

**判断**: 「无提现权限 ≠ 安全，小币种对敲照样能把钱搬走」这条是绝大多数同类工具不敢说的真话，也是我们该在文档里复述的。稳定币脱锚风险那条同样重要——我们的价差计算如果隐含 1 USDT = 1 USDC，脱锚时整个套利模型失效。这套坦诚的风险文案本身就是产品信任资产。

### taoli-tools-signer：助记词签名服务

**是什么**: 开源的自托管签名服务（TypeScript/Hono，24 stars），把助记词变成一个 HTTP API，让前端像调用中心化交易所 API 一样调用它，助记词不再进入 Taoli Tools。keychain.toml 格式：`[api-key-name]` 下配 `secret`（至少 32 字符）、`mnemonic`、可选 `ip = [...]` 白名单、可选 `passphrase`。一个文件可配多个命名钱包。鉴权用 HMAC-SHA256 对原始请求体签名放在 `X-SIG` 头，服务端还校验来源 IP。CORS 硬锁 `https://taoli.tools` 和 `http://localhost:5173`。API 面：`GET /:key/:platform` 返回地址，`POST /:key/:platform` 返回签名后的交易字节，platform 只有 EVM 和 SVM。

**怎么实现**: HMAC-SHA256(secret, raw_body) → base64 → `X-SIG` 头；IP 白名单从连接信息取 remote address 比对；KEYCHAIN 从 Cloudflare Worker secret 或 `/run/secrets/KEYCHAIN`（Docker secret）读取，memoize 缓存。只使用助记词派生的**第一个地址**（EVM 走 viem 默认路径，SVM 走 `m/44'/501'/0'/0'`）。

**判断**: **这是四个开源仓库里最有工程价值的一个**。使用场景：套利的一条腿在链上 DEX（现货）另一条腿在 CEX（永续）时，不想把热钱包私钥放进随时可能被插件/木马攻破的浏览器，或者跑在租来的云服务器上。如果我们的工具只做六家 CEX，暂时用不上；但一旦要加链上腿，这个架构（签名服务与交易逻辑进程隔离 + HMAC + IP 白名单 + 合约白名单）就是现成的正确答案，直接照抄。

### Signer 的硬编码合约白名单 + 拒绝原生转账

**是什么**: README 把「Contract allowlist」列为 feature，但**实际不是用户可配的**——keychain.toml 的 schema 只有 secret/ip/mnemonic/passphrase，白名单硬编码在 `src/platforms/evm.ts` 和 `svm.ts` 里。EVM 侧规则：(1) 交易必须有 data 和 to，否则 `Invalid transaction`；(2) **`tx.value` 非零直接拒绝（`Forbidden value`）**——即完全禁止转原生币；(3) `to` 必须在按 chainId 索引的白名单里（OKX DEX router 及 approve 合约、1inch、Odos、Uniswap V2/V3/V4 + Permit2、PancakeSwap V2/V3/Infinity + Permit2、Aerodrome），否则尝试按 erc20Abi 解码，只允许 `approve` 且 spender 也必须在白名单里，否则 `Forbidden approval` / `Forbidden to`。SVM 侧：交易里**每一条** instruction 的 programId 都必须在白名单（ComputeBudget、Associated Token Account、OKX DEX `proVF4pMXVaYqmy4NjniPh4pqKNfMmsihgd4wdkCX3u`、Jupiter `JUP6LkbZbjS1jKKwapdHNy74zcZ3tLUZoi5QNyVTaV4`）里，否则 `Forbidden program`。

**怎么实现**: EVM：`if (tx.value && tx.value !== 0n) throw 'Forbidden value'`；`allowlist[getAddress(tx.to)]?.has(chainId)` 否则回退到 `decodeFunctionData({abi: erc20Abi})` 只放行 approve 且 `allowlist[spender]?.has(chainId)`。SVM：遍历 `compiledTransactionMessage.instructions`，每个 `staticAccounts[instruction.programAddressIndex]` 都必须命中 allowlist。

**判断**: **这才是 signer 真正的安全价值**，比 HMAC 重要得多：即使前端被完全攻破、攻击者能任意构造交易让 signer 签名，他也无法转走资产——原生币转账被 value 检查挡死，代币转账被 to 白名单挡死（transfer 不是 approve），恶意 approve 被 spender 白名单挡死。这是一个"签名服务不信任调用方"的教科书实现。任何涉及链上私钥的场景都该照抄这个模式。注意向用户说明时不要照搬 README 的措辞——它暗示白名单可配，实际是编译期固定的，要改必须改代码重新部署。

### Windows 服务器保活 runbook

**是什么**: 一份非常细的挂机运维清单：选阿里云/腾讯云轻量应用服务器、**东京地域**（因为大部分交易所服务器在东京）、Windows Server 2022、2核4G起（Pair 多了要更高）；改掉默认用户名 Administrator 和默认端口 3389（防暴力破解锁号）；禁用 Windows 自动更新；禁用 Edge/Chrome 的标签页休眠和省内存/节能模式，并把 `https://taoli.tools` 加入「始终保持活跃」白名单；用 Logout.bat + 管理员身份快捷方式避免断开远程桌面后自动锁屏；装 PowerToys 开 Awake 防系统休眠。

**怎么实现**: 东京地域 + 2C4G 起；改默认用户名和 RDP 端口；关 Windows Update；关浏览器休眠/省电模式；PowerToys Awake 防休眠；Logout.bat 防锁屏。延迟目标：交易所 ping < 150ms。

**判断**: 这是 1.5 年运营沉淀的"7×24 挂机不掉线"知识，和产品架构无关，是**通用的加密交易运维知识**，对我们同样适用（用户已有 5.78.104.216 服务器和 Windows 服务器跑脚本）。特别是「东京地域」这条——交易所延迟直接决定 FOK 限价单的成交率，我们的 500ms 收敛循环对延迟敏感度更高。「改 3389 默认端口防爆破」和用户已有的 fail2ban 经验一脉相承。

### 单腿补单与追单（Shift 隐藏操作）

**是什么**: 出现红色错误信息时，按住 Shift 或 Alt 会出现 `✓` 按钮，后面跟着可重试的交易方向和 size，点击即市价补单；未成交委托列表同样按 Shift/Alt 后把取消按钮变成 `✓` 市价追单按钮。两者都**没有二次确认**。文档明确：「在工具内操作成功的补单/追单，可以正确计算到其对应的 PnL」。追单实现坑：有些交易所没有修改委托接口，实现方式是先取消再重新下单，因此可能出现"取消了委托但没重新下单"。

**怎么实现**: Shift/Alt 修饰键唤出隐藏操作；市价补单方向和 size 由工具根据失败信息推算；追单在无改单接口的交易所退化为撤单+重下（非原子，有裸奔窗口）。

**判断**: 「单腿修复要走工具内的按钮而不是去交易所手动操作，否则 PnL 算不对」——这个约束我们必须在设计之初就想清楚：任何绕过工具的手工操作都会污染 P&L 账本。这是对账功能的隐含前提。修复按钮本身应该做，但**要加二次确认**（taoli 没有，是个明显的可用性 bug）。「先撤后下」的追单实现风险也值得记下来。

### 产品定位的自我限制（不是什么）

**是什么**: 文档首页直白写：「不是无风险的摇钱树 / 不能帮你全自动赚钱 / **不能自动化执行策略**」。下单操作页警告 Loop「可能会出现只有单边成交的情况，**如果想要无人值守需谨慎**」，以及「**请不要关闭或最小化网页，会导致无法触发下单**」。

**怎么实现**: 产品定位层面。技术上「最小化即失效」源于浏览器对后台 tab 的 timer 节流。

**判断**: 这是 taoli.tools 和 qqq.bot 的**根本分野**：taoli 是半自动的"手动挡"（人盯着，Loop 只负责在价差满足时下单），qqq.bot 才是策略规则引擎的"自动挡"。我们的工具定位在哪一端决定了整个架构。真实运营 1.5 年后仍然坚持"不能无人值守"，这个信号值得重视——跨所套利的单腿风险可能确实不适合完全无人值守，至少必须配足够强的告警（回到第 1、2 条）。另外「关闭或最小化网页就不下单」是浏览器后台节流的必然结果（用户已知的"后台标签 setInterval 节流"经验），又一条纯前端架构的硬伤。

### 生态外包：第三方监控工具清单

**是什么**: 文档专列「第三方工具」页，收录群友做的工具（部分由 Taoli Tools 赞助但不承担责任）：TAOLI OPS 套利监控系统 taoli.asia、KAI 差价监控、PAOPAO 监控（多交易所套利与资金费率预警）、OKX OnchainOS API Proxy、Cross-Chain Bridge、以及 TG Bot（币探——查询/订阅充提状态&指数成分、价差监控通知、会计——收益计算机器人、newcoin）。配套的「开发者激励计划」用免费 VIP2 换第三方小工具（条件：不收费、功能与套利相关但**不与 Taoli Tools 重叠**），付费群投票选出，已于 2026 年 1 月暂停。

**怎么实现**: 生态运营手段。技术上要抄的是"充提状态（deposit/withdraw enabled）+ 链选择 + 到账确认数"的监控，六家 CEX 的 currencies 接口都有这个字段。

**判断**: 直接回答"taoli 有哪些 ops 能力"：**它把监控告警和充提状态查询外包给了生态**。这暴露了两个它没做的功能，正是我们的机会：(1) **充提状态监控**（币探 Bot 的核心功能）——跨所搬砖最致命的是搬过去发现提币关闭了，这必须做进工具；(2) 独立的价差/资金费率预警系统。开发者激励计划本身也是个聪明的低成本护城河打法（用 VIP 额度而非现金换生态），但对我们这个阶段不适用。

### Sequence 三模式：Parallel / A then B / B then A

**是什么**: 双腿下单顺序可选：同时下、A 成功后再下 B、B 成功后再下 A。串行模式下前腿失败则后腿不下单，且 Loop 不停止（只警告）。

**怎么实现**: 文档建议「哪边容易失败就优先哪边」。明确警告：无论哪种模式都可能单腿；且「如果交易所 API 返回成功但实际没下单成功，仍会被认为成功」。

**判断**: should — 我们六家全是 CEX，同质性比它高，Parallel 大多够用。但 HTX/Gate 的 API 稳定性明显差于 Binance/OKX，串行「先下差的那腿」能显著降低单腿率。实现成本很低（一个枚举 + 顺序控制），建议做。

### 现货杠杆腿 + 六家借币利率数据源

**是什么**: A/B 两腿各自可以是 Spot（现货）/ Isolated（逐仓杠杆）/ Cross（全仓杠杆）/ Perp（永续）四种类型任意组合。交易页面 Fee 栏对永续显示下次资金费，对现货杠杆显示每小时利息，点击看历史。设置页可导出 Lending 借贷利息记录 CSV。

**怎么实现**: 实测抓到的借贷数据源：Bybit /v5/spot-margin-trade/data、OKX /api/v5/public/interest-rate-loan-quota、Bitget /api/v2/margin/currencies + /v1/margin/opt/system/getIsolatedConfig + getCrossConfig、Gate /api/web/v1/uniloan/uni-loan-loan-info?loanType=1|2、Backpack /api/v1/borrowLend/markets、以及它自建的 taoli.tools/binance-cross-margin-info。现货杠杆在 Binance/Bybit/Bitget/Backpack/Gate 五家可用。

**判断**: should — 这是「借贷」在 taoli.tools 里的真实形态，**不是理财挖矿产品，是保证金腿的成本项**。价值在于打开 spot-perp basis 和「现货杠杆做空 + 永续做多」这类策略，同时把借币利率算进净收益。我们六家里 Binance/Bybit/Bitget/Gate 四家有杠杆，值得做。但优先级排在纯 perp-perp 之后——先把双永续跑通再加。

### Risks 三件套：ADL 优先级 + 归一化保证金率 + 爆仓价距离

**是什么**: 交易页面每腿一个 Risks 列，显示三种风险指标，按危险度着色（红/黄/绿/灰四级）：(1) ADL 自动减仓优先级，5 档从左到右概率递增；(2) MR 保证金率；(3) Liq Price 清算价。

**怎么实现**: ADL 支持所：Binance、Bitget、Bybit、Gate、OKX（正好覆盖我们六家里的五家）。MR **统一归一化为 Binance 口径**：权益/保证金，数字越大越安全，>100 时不显示（各所原始口径不同，通常取一次倒数）。爆仓价距离：市价=(买一+卖一)/2，爆仓价百分比 = 爆仓价>市价 ? 爆仓价/市价 : 市价/爆仓价。文档诚实提示「没数据就不显示，但不代表没风险」。

**判断**: should — qqq.bot 是 ADL **之后**才降 target + 锁 reduce-only，属于事后止损；taoli.tools 是**事前**把你在 ADL 队列里的位置摆出来。两者应该都有：事前看板 + 事后自动降档。MR 的跨所归一化口径（统一成 Binance 的权益/保证金）是个现成的、省事的标准化决定，直接抄。

### 双向 Loop 同时挂 + 阈值不对称

**是什么**: 同一个交易对的 -A+B 和 +A-B 两个方向可以同时点亮 Loop，差价在区间内来回震荡时两个方向反复吃，等于在价差上做市，而不是「开仓-等-平仓」的单次往返。两边预设差价不必相同，允许一边为负。

**怎么实现**: FAQ 给了判据：只要两个方向的差价数字加起来 > 两边手续费之和的 2 倍，理论上就是赚的。举例：A 费率 0.1%、B 费率 0.05%，则两个差价之和需 ≥ 0.3%。工具里根本没有「开仓/平仓」概念，只有 -A+B 和 +A-B 两个方向。

**判断**: should — 思路非常漂亮，且几乎零额外基础设施：把套利从「事件」变成「持续做市」，收益来自差价震荡频次而非单次幅度。取消开/平仓的心智模型也更干净。我们的规则引擎里加个「双向同时武装 + 各自阈值」就行。注意这个玩法要求两边阈值之和覆盖 2 倍总手续费，这个约束要在 UI 上直接算给用户看。

### 手续费与 PnL 的币种记账

**是什么**: PnL 区域按「一次触发产生的两笔订单」成对合算，手续费含在内。关键是区分手续费计价币种：买入现货用币扣手续费，其余三种情况（卖出现货、做多合约、做空合约）扣 U。平台币抵扣（BNB、GT、POINT）和链上 Gas 也计入 PnL。

**怎么实现**: FAQ 专门解释了「现货少点零头」现象：买现货扣币导致到手数量总是少一点，建议手动补一点点现货。PnL 每行的价格是**触发下单价**而非成交价，时间是**本机触发时间**。设置页可导出与 PnL 区域完全一致的 CSV。

**判断**: should — 手续费币种这件事不建模，账永远对不上，而且会掩盖真实盈亏（用户以为赚了其实在亏）。GT/BNB 抵扣尤其影响 Gate/Binance 的实际成本。我们做净收益排序时必须扣真实手续费——顺带说，qqq.bot 的榜单连手续费都不扣，这也是个明确差距。

### 通知：4 通道 × 6 事件类型（含明确检测周期）

**是什么**: 通道：Web 推送 / Telegram Bot / Lark Webhook / Bark。事件：Order（工具触发下单，非成交）、Warn（现货余额不足、超 MaxO/MinA/MaxA、A then B 时 A 出错）、Stale（价格 5 分钟没更新，每 60 秒检测）、Error（出现红字）、Risks（Risk 出现红字，或勾了 FLAT 但两边不平衡，每 15 秒检测）、Price（价格超出设定安全范围，每 30 秒检测）。

**怎么实现**: TG 需填 Bot Token 且创建后要手动点一次 Start；Lark 填 Webhook URL；Bark 填 Server URL。

**判断**: should — 事件分类和检测周期是现成的、被 1.5 年运营验证过的默认值，直接抄省得自己试。我们用户已经在用微信推送（memory 里 crypto_social_tracker 那套），通道复用即可，重点抄它的**事件分类学**：把「下单触发」和「成交」分开、把 Warn 和 Error 分级，这两个划分很实用。

### 单交易所多账户（Unique Name）

**是什么**: 添加交易所时先填一个自定义 Unique Name 再选交易所，因此同一家交易所可以添加多次（多个 API Key / 多个子账户）。可点名字重命名。点 ⟳ 测该所 ping 延迟。

**怎么实现**: 文档警告重命名可能导致已有 Pair 和 PnL 出错（说明它是拿名字当主键的，这是个设计缺陷，我们应该用稳定 ID + 显示名分离）。ping 建议不超过 150ms，超了建议换服务器。VIP 资金量统计上，相同交易所账户/钱包添加多次不重复计算。

**判断**: should — 这是它最接近「批量账户管理」的东西，但也就到此为止：**没有任何批量下单/批量配置/统一风控的多账户编排 UI**，多开靠开多个浏览器 profile（--user-data-dir）。我们抄「一所多账户」这个数据模型即可（而且要修掉它拿名字当主键的坑）。真正的批量账户管理是空白市场，如果我们要做差异化，这里是个口子。

### 交易对搜索：精确匹配 + 异常状态标记

**是什么**: 搜索框普通搜索只展示 50 个结果，**末尾加「/」启用精确匹配并展示全部结果**。已下架的交易对标 `!` 感叹号，处于非正常状态（盘前盘后、只能减仓不能加仓）的标 `?` 问号。也可直接粘贴合约地址添加自定义链上代币。

**怎么实现**: Spot=现货，Isolated=逐仓杠杆，Cross=全仓杠杆，Perp=永续，在选择器里直接标类型。不搜索时默认显示当前有持仓的交易对。

**判断**: should — 下架/只减仓标记能直接防住「开了仓平不掉」这类事故，Bybit 的 PreLaunch、Binance 的下架公示期都会踩。「/」结尾精确匹配是个很省事的交互技巧。默认显示有持仓的对也很贴心。

### 双向同时 Loop —— 用差价做网格

**是什么**: -A+B 和 +A-B 两个方向可以同时点亮 Loop，且两个方向的预设差价可以设成不同值、甚至允许一边为负。差价来回震荡时两个方向反复成交，不断吃差价。

**怎么实现**: 文档原话思路：不必等到最后才平仓，从一开始就把两个方向的 Loop 都点亮，中间差价反复时两个方向都能反复下单；两边差价不必相同，只要两数之和 ≥ 2×(feeA+feeB) 理论上就是赚的。

**判断**: 这是 taoli.tools 有而 qqq.bot 结构上做不到的玩法。qqq.bot 的规则引擎是棘轮式的、target 只能单向调，天然只能"开仓→持有→平仓"，无法在同一个 pair 上双向反复收割。跨所价差是均值回归的，双向 Loop 才是价差套利的正确形态。我们的策略引擎应当支持每个 pair 挂两组独立阈值。

### 四道仓位闸门（MinA/MaxA/$MinA/$MaxA）

**是什么**: MinA/MaxA 以币为单位限制 A 腿最小/最大持仓；按住 Shift 出现 $MinA/$MaxA 以 U 为单位限制持仓市值。四个同时填写时是 AND 关系（都必须满足）。触发时黄字暂停下单但不停 Loop。只限制 A 腿，不限制 B。未成交的黄色挂单也计入。

**怎么实现**: 下单前预判"仓位数量即将小于/大于"，报 `A: Position will be less than MinA` / `A: Position value will be greater than $MaxA`。文档明确承认可能因请求延迟或持仓未及时更新超出一两单。

**判断**: 币本位 + U 本位双口径是关键细节：币本位闸门在币价暴涨时会失效（数量没变但市值翻倍），U 本位闸门在币价暴跌时会失效（市值缩水但数量堆积）。两个 AND 起来才是真闸门。qqq.bot 只有单一 target。另外"把未成交挂单计入持仓判定"这一点必须抄，否则挂单堆积会导致实际敞口远超预期。

### Flat 持仓平衡校验

**是什么**: 勾选 Flat 后，每次双边下单前检测两腿持仓是否平衡；若 A 与 B 持仓绝对值相差 ≥ 一个 Size，则黄字警告、不下单、但不中断 Loop。

**怎么实现**: 判据写得很明确：Position + 该腿所有未成交订单总量，A、B 两边加起来是否等于 0。

**判断**: 这是 delta 中性的守门员，而且判据把"未成交挂单"算进去了——这正是限价模式下最容易出现的隐形单腿（A 已成交、B 还挂着）。qqq.bot 靠 500ms 收敛循环去追平，但没有"不平就拒绝加新仓"这道刹车。我们做限价单时必须有这条，否则不平衡会滚雪球。

### Sequence 腿序控制（Parallel / A then B / B then A）

**是什么**: 三种下单顺序：Parallel 两腿同时下；A then B 等 A 成功再下 B，A 失败则 B 不下且 Loop 不停；B then A 反之。文档建议"哪边容易失败就优先哪边"。

**怎么实现**: 注意文档明说的坑：如果交易所 API 返回成功但实际没成交，仍会被判为成功；以及 A then B 模式下 A 误判失败会直接产生单腿且不生成 PnL 记录。

**判断**: 六家所里 HTX/Gate 的下单成功率和延迟明显差于 Binance，先打脆弱腿再打稳健腿能显著降低单腿率。qqq.bot 只有并行下单。实现成本很低（一个下拉框 + await 顺序），但要连带把"API 返回成功≠真成交"的对账逻辑做上，否则 A then B 反而制造新的单腿来源。

### 单腿一键市价补单/追单，且计入 PnL

**是什么**: 出现红字单腿错误时，按住 Shift/Alt 会出现 ✓ 按钮，后面跟着可重试的方向和 size，点一下市价补单。未成交挂单也能按 Shift 变成 ✓ 做市价追单。在工具内完成的补单/追单会被正确计入对应的 PnL。

**怎么实现**: 没有二次确认；追单可能需要点多次；部分交易所没有改单接口，实现是"先撤再下"，因此可能出现撤了没重下的窗口期。

**判断**: 单腿修复是这类工具的真实高频操作，前作把它做成了"错误信息旁边直接给一个按钮 + 自动带好方向和数量"，而不是让人去交易所手点。更重要的是补单会并入原 pair 的 PnL 核算——qqq.bot 里手动去交易所补的仓会让 PnL 账目对不上。这个交互值得原样抄。

### 三合一风险条：ADL / MR / 爆仓价

**是什么**: 每个 pair 每腿显示 Risks：ADL 自动减仓优先级（五格图标，从左到右概率递增，支持 Binance/Bitget/Bybit/Gate/OKX）、MR 保证金率（数字，>100 时不显示）、Liq Price 清算价（$ 开头）。四色分级：红>黄>绿>灰。按 Shift 切换为持仓均价 Average。

**怎么实现**: MR 统一采用币安口径：权益/保证金，数字越大越安全（对其他所返回值通常取倒数后处理）。爆仓价百分比 = 市价取 (买一+卖一)/2，然后 爆仓价>市价 ? 爆仓价/市价 : 市价/爆仓价。

**判断**: qqq.bot 只在 ADL/强平"发生后"降 target 并锁 reduce-only，是事后补救。前作是把 ADL 优先级、保证金率、爆仓距离三个前瞻指标常驻在界面上。尤其"把各所 MR 统一成币安口径"这个归一化处理，是六所工具必须做的——否则一个所的 0.05 和另一个所的 20 摆在一起没法读。爆仓价百分比公式也直接可用。

### 历史差价 K 线图（按方向分开）

**是什么**: 点击 -A+B 或 +A-B 可查看该交易方向的历史差价图表。左上角可选蜡烛宽度单位，以及按 OHLC 中的哪一个数字来计算差价。另有历史资金费率面板、该 pair 的持仓资金费收支明细、以及该永续合约的指数成分展示。

**怎么实现**: 当前差价公式明确：-A+B 差价 = (A Bid1 - B Ask1)×2/(A Bid1 + B Ask1)×100%；+A-B 差价 = (B Bid1 - A Ask1)×2/(B Bid1 + A Ask1)×100%。注意分母用的是两价均值而非单边价。链上 pair 需要至少配一组 OKX DEX API Key 才能看差价 K 线。

**判断**: 差价的历史分布决定预设差价该填多少——没有这张图，用户只能拍脑袋。公式里用 (bid+ask)/2 做分母而不是单边价，是个正确的细节（避免方向性偏差），可以直接抄。"指数成分"展示是隐藏彩蛋：能提前发现某个永续的指数只挂了一两家小所，是被操纵/插针的高危信号。

### 6 类通知 × 4 通道

**是什么**: 通道：Web 网页通知 / Telegram Bot / Lark Webhook / Bark。类型：Order（工具内触发下单，非成交）、Warn（现货余额不足、超 MaxO/MinA/MaxA、A then B 时 A 出错）、Stale（价格 5 分钟未更新，每 60 秒检测）、Error（pair 下方出现红字）、Risks（Risk 出现红字或勾了 Flat 后两边不平衡，每 15 秒检测）、Price（价格超出设置的安全范围，每 30 秒检测）。

**怎么实现**: 各类型有独立的检测周期：Stale 60s、Risks 15s、Price 30s。

**判断**: 这套分类是运营 1.5 年沉淀出来的——每一类都对应一种真实的亏钱路径。特别是把 Risks（含 Flat 不平衡）和 Price（价格越界）单独拆出来并给不同轮询周期，比笼统的"出错了通知你"有用得多。我们已有微信推送通道，套这套类型表 + 周期表即可，几乎零设计成本。

### N 面值换算系数

**是什么**: 添加交易对的 Advanced 面板里有 N 参数：一个单位的 A 等于多少个单位的 B。绝大多数情况填 1。

**怎么实现**: 文档原例：A 是 1MCHEEMS、B 是 1000CHEEMS，则 A = 1000×B，N 填 1000。复制反向 pair 时 N 自动取倒数、MinA/MaxA 对调、Sequence 也跟着变。

**判断**: 六家所对同一个 meme 币的合约面值命名极不统一（1000PEPE / 1MPEPE / PEPE），不做换算系数就会出现 1000 倍的敞口错配——这是能一次亏光的错误。qqq.bot 未见此机制。实现只是一个乘数，但必须在"持仓平衡判定"和"差价计算"两处都乘上去。

### 交易/资金费/利息三套 CSV 导出 + 交易小票图片

**是什么**: 设置页第三列可导出三类记录：Trading 交易记录（按日期出总表 + 按 pair 的 A/B 筛选出分表）、Funding 永续资金费记录（最近 7 天总表 + 单 Ticker 分表）、Lending 现货杠杆利息记录。每条记录三种导出方式：浏览器内直接展示 CSV / 通过 Telegram Bot 发送 / 下载。另有"交易小票"图片，字段实测含 DATE、PROFIT & LOSS、FEE & GAS、VOLUME、TOTAL、UID、RPC、VA、VB，SYMBOLS 和 EXCHANGES 默认隐藏可点开。

**怎么实现**: 小票用 snapDOM 做 DOM 截图生成 PNG（代码里可见 `TAOLI TOOLS FUNDING.png`、`HTTPS://TAOLI.TOOLS` 水印）。PnL 区域数据与导出的 CSV 完全一致。PnL 计入平台币抵扣手续费和链上 Gas（BNB/GT/POINT）。

**判断**: 两件事值得抄：一是"总表 + 按 pair 分表"的双层导出结构，做归因时必须按 pair 拆；二是 PnL 必须把平台币抵扣和 Gas 算进去，否则 BNB 抵扣的 25% 手续费会让你误以为策略比实际赚。小票默认隐藏 symbol 和交易所是个聪明的隐私默认值（方便晒单又不泄露自己在做哪个币）。

### 部署与延迟建议（东京机房 / ping<150ms）

**是什么**: 文档给出明确的延迟纪律：交易所设置页 ⟳ 按钮测 ping，最好不超过 150ms，超了就上服务器。推荐地域是亚太-东京，理由写明"大部分交易所的服务器都在东京"。推荐配置 2 核 4G 起，pair 加多了要更高。三种部署形态：本地浏览器 / Windows 服务器远程桌面 / Linux Docker + VNC。

**怎么实现**: 另有配套的时间同步排障：出现 recvWindow / timestamp 类报错说明本机与交易所时差 >5 秒，建议换东京服务器或校准系统时间后重启浏览器。

**判断**: 我们是 Python + NiceGUI，天然是服务端程序，可以直接把"每个所的实时 ping"做成常驻指标并在超阈值时降级（比如禁用市价单、拉大 V 参数）。150ms 这个经验阈值和"东京"这个落点是运营 1.5 年的结论，直接采信。时钟漂移检测也应该做成启动自检。

### 公开资金费率筛选器作为首页（免登录漏斗）

**是什么**: taoli.tools 根路径 `/` 不是营销落地页，而是一个可直接用的全交易所永续资金费率榜，不需要登录、不需要 API Key。右上角一个逐字母彩虹循环变色的「开始交易 ->」按钮跳 /trade。底部只有三个外链：文档↗ / 电报群↗ / 浏览器插件↗，加主题和语言切换。

**怎么实现**: React Router 路由 routes/index，客户端直接并发调 6 家交易所的 fetchTickers()（concurrency 6，每 300 秒刷新），前端聚合。选中某行后 document.title 会实时变成 `Binance BTC +0.0123% | Taoli Tools`，把浏览器标签页当成行情条。

**判断**: 这是它 1.5 年长成 5487 人 TG 群的获客入口：先给一个白嫖也有用的公共数据页，再把付费产品挂在角落。我们的工具如果只有登录后才有内容，就没有这个漏斗。而且「标签页标题当 ticker」这种小心思几乎零成本。

### 交易所多选复选框 + 数据缺失自动置灰

**是什么**: 滑块下方一排交易所复选框（每个交易所一个），末尾一个 ⟳ 手动刷新按钮。全不勾 = 全部显示（而不是全部隐藏）。当前数据里没有该交易所时，复选框自动 disabled。

**怎么实现**: 只渲染实现了 fetchFundingRateHistories 的交易所；每次重算过滤结果时同时收集出现过的 exchange 集合，用它决定哪些框可用。

**判断**: 「全不勾=全选」这个默认值处理省掉了一个空态；自动置灰避免用户勾了个没数据的交易所然后以为程序坏了。六家所的场景下这套非常合适。

### 资金费历史面板：时间比例条形图 + 指数成分

**是什么**: 点表格任意行，右侧滑出一个窄面板（约 13rem）：顶部一行 `24H +1.23%  7D +4.56%`（窗口内费率求和，正绿负红）和 ⨯ 关闭；中间是历史资金费列表，每行左边是带符号的费率（4 位小数）、右边是 MM-dd HH:mm 时间，整行背景是一条按 |rate|/max|rate| 缩放的横向色条，负值向左延伸、正值向右延伸；最下方列出该永续合约的指数成分（成分交易所、价格、权重%）。

**怎么实现**: 色条用 CSS linear-gradient 画，不用图表库。关键细节：每行的 padding-top = ((上一条时间 - 本条时间)/3600000 - 1) * 16px，也就是缺失的结算周期会自然留白，用垂直空白表达时间间隔。数据每 300 秒刷新。

**判断**: 「用 CSS 渐变 + 行内 padding 画时间比例条形图」是零依赖、零布局抖动的做法，在 NiceGUI 里同样可以纯 CSS 实现。指数成分展示也是我们没想到的点：能提前发现某个永续的指数只挂在一个小所上（操纵风险）。

### 修饰键作为「第二层 UI」

**是什么**: 设置页可选 Shift / Ctrl / Alt 作为 Modifier Key。在 trade 页按住它，整屏控件切换成另一套：MinA/MaxA 输入框变成 $MinA/$MaxA（币本位↔U 本位）；未成交挂单后面的 ⨯ 取消按钮变成 ✓ 市价追单；报错红字行出现 ✓ 加方向和 size 的一键补单；Pair 操作区的 ⨯删除/◫复制/-最小化 变成 ↑上移/◧镜像复制(A B 互换、N 取倒数、MinA/MaxA 对调、Sequence 反转)/↓下移；Risks 列变成持仓均价；Fee 列变成费率上下限；Last 列变成价格安全区间输入；差价图十字光标从磁吸变自由。

**怎么实现**: 全局一个 boolean 状态，keydown 匹配配置的键名就 toggle；界面上按住时整个中央列会出现蓝色 inset ring 作为「你现在处于第二层」的提示。

**判断**: 这是它把极高密度塞进一屏的核心手法，也是把「危险操作」（追单、补单、镜像复制）藏在一层门槛后的安全设计。NiceGUI 可以用 ui.keyboard 实现。但要注意它的短板：追单和取消都没有二次确认，文档明说「可能需要点多次」，我们抄机制不抄这个鲁莽。

### 底部 P&L 横向流水条

**是什么**: 页面最下方一条固定高度（min-h-24）的横向滚动区，每笔配对交易一张窄卡：第一行 `-A <账户名> <BASE/QUOTE 类型> <触发价>`，第二行 `+B ...`，第三行 size + 本机触发时间（精确到毫秒的 title），后面 N 行是按币种聚合的实际净盈亏（正绿负红，含手续费、平台币抵扣和链上 Gas）。

**怎么实现**: 鼠标滚轮垂直滚动被劫持成横向滚动（deltaX===0 时 preventDefault 并 scrollLeft += deltaY）。每张卡用 IntersectionObserver 判断是否可见，只有可见时才每 5 秒去交易所拉 fills 算真实成交盈亏，一旦某币种算出非 0 就停止轮询。注意它显示的价格是「触发下单价」不是成交价。

**判断**: 两点值得抄：滚轮转横向滚动（横向流水的必备手感），以及「只在可见时轮询、算出结果就停」的懒加载策略——六家所的 fills 接口都有限频，这个模式能省掉大量无用请求。

### 战绩小票分享卡（稀有度分级 + 打码开关）

**是什么**: 设置页第三列点任意导出按钮，会渲染一张 64 单位宽的「小票」卡：顶行是稀有度名 + `APR xx.xx%`；中段是 TICKER(S)/TOKEN(S)、EXCHANGE(S)、DATE(单日或区间)、PAYMENT TIMES 或 TRADE(S) 计数、TOTAL 或 VOLUME/PROFIT & LOSS/FEE & GAS；底部 logo + `HTTPS://TAOLI.TOOLS`。币种和交易所默认打码（`???/???` 和 `****`），点一下才展开。右侧三个按钮：复制 PNG 到剪贴板 / 发到自己的 Telegram / 下载为 `TAOLI TOOLS FUNDING.png`。

**怎么实现**: 稀有度按日化收益率 d = 收益/本金/天数 分档：d≥0.16 SCAM（彩虹 conic-gradient 边框）、≥0.05 LEGENDARY(玫红)、≥0.016 GODLIKE(琥珀)、≥0.005 MASTER(紫)、≥0.0016 MAGICIAN(天蓝)、≥0.0005 SEEKER(翠绿)、否则 NEWBIE(灰)。卡上 APR = d*36525。截图用 DOM-to-image 转 blob，Telegram 走 sendPhoto。交易小票还有个 average/median 的计价基准切换。

**判断**: 这是把「本地工具」变成社群传播机器的关键，而且打码开关解决了晒单的隐私顾虑——用户敢发了才有传播。稀有度命名（尤其 ≥16% 日化直接叫 SCAM）是很聪明的自嘲式风控提示。qqq.bot 完全没有这层。我们做完核心功能后，这是性价比最高的增长功能。

### 四通道 × 六类型通知矩阵

**是什么**: 通知渠道 4 种：Web(浏览器通知，需授权) / TG(填 Bot Token，且要先点 Bot 的 Start) / Lark 飞书(Webhook URL) / Bark(Server URL)。通知类型 6 种，每种都有明确触发条件：Order(工具内触发下单，不是成交)、Warn(现货余额不足、超过 MaxO/MinA/MaxA、A then B 时 A 出错)、Stale(价格 5 分钟没更新，每 60 秒检测)、Error(Pair 下方出现红字)、Risks(Risk 出现红字，或勾了 FLAT 后两边不平衡，每 15 秒检测)、Price(价格超出设置的安全范围，每 30 秒检测)。

**怎么实现**: 每类是独立的定时查询任务（refetchInterval 15/30/60 秒），命中即推送；渠道和类型是正交的勾选矩阵。

**判断**: 通道选型对中文加密用户完全对路（TG + 飞书 + Bark，没有邮件没有短信）。更值得抄的是「六个类型各自有独立检测周期和明确定义」——比一个笼统的『开启通知』开关有用得多。我们已经有微信推送链路，加一个正交矩阵成本很低。

### 三种交付方式的 CSV 导出（网页 / Telegram / 下载）

**是什么**: Trading / Funding / Lending 三类历史记录，每一条记录都提供三个导出按钮：Webpage(在浏览器新开一个 800x400 小弹窗直接把 CSV 渲染成对齐的表格)、Telegram(通过 Bot 发 csv 文件给自己)、Download(存文件)。Funding 是最近 7 天，可选总表或按 Ticker 分表；Lending 必须先选 Ticker；Trading 第一条是所选日期总表，后面按 Pair 的 A/B 分表。代币列表还支持 Import CSV 批量导入自定义代币。

**怎么实现**: Webpage 模式生成一个内联样式的 Blob HTML（等宽字体 <pre> + CSV 对齐）后 window.open；Telegram 走 sendDocument。

**判断**: 「Webpage 预览」这一档是真聪明——用户 90% 的时候只是想看一眼，不想下载文件再找 Excel。这个三档交付（看 / 发给自己 / 存盘）在我们的报表功能里可以原样复制，NiceGUI 直接渲染表格更简单。

### VIP 超限的倒计时宽限带（而非直接封停）

**是什么**: 资金量超过 VIP 上限或订阅过期时，页面顶部出现红色横幅（`资金额超过限制，升级 VIP 以继续交易。`）并带一个 `(2:59)` 倒计时；倒计时期间还能继续交易，归零后所有下单状态被清空、Pair 全部禁用。接近限制（>90%）或即将到期时是黄色横幅，不影响交易。横幅里还内嵌当前资金额和总资金额的可点击明细。

**怎么实现**: 180 秒 setInterval 递减，归零时把两个方向的运行状态字典置空。四条文案是 i18n 的 expired / exceeded / almost_expired / almost_exceeded。

**判断**: 付费墙的 UX 范本：先黄后红、红了还给 3 分钟平仓窗口，而不是当场断线导致单腿。我们如果做付费/额度，这个「宽限倒计时」必须抄——套利工具中途断线是要出事故的。

### 价格安全区间（每腿独立的上下界）

**是什么**: 按住修饰键时，Last(现价) 列会变成两个输入框 `下限 ~ 上限`，为 A 和 B 各自设置价格安全区间（aPriceLower/aPriceUpper/bPriceLower/bPriceUpper），步进取该交易对的 priceStep。超出区间会触发 Price 类型通知（每 30 秒检测）。

**怎么实现**: 存在 pairConfig 里，下限的 max 绑上限、上限的 min 绑下限做联动校验。

**判断**: 这是「无人值守时的兜底闸门」，比单纯的止损更适合对冲场景（币价跑到离谱区间说明假设已破）。qqq.bot 没有对应物。实现成本几乎为零。

### Ctrl/Cmd+F 聚焦搜索 + 表头即搜索框

**是什么**: 资金费首页的表格里，Symbol 那一列的表头不是文字，而是一个 placeholder 为「币种」的输入框，聚焦后 placeholder 消失、背景变深；全局监听 Ctrl/Cmd+F 抢占浏览器查找、直接聚焦这个框。搜索支持末尾加 `/` 切精确匹配。

**怎么实现**: document.addEventListener('keydown') 里判断 key==='f' && (ctrlKey||metaKey) 后 preventDefault + focus。

**判断**: 表头位置复用成搜索框省一整行；劫持 Ctrl+F 是对的，因为用户在这个页面按 Ctrl+F 想找的就是币种。两个都是零成本细节。

### 整站视觉语言：等宽字体 + 字符按钮 + 无边框

**是什么**: 全站 `text-xs font-mono`（Fira Code VF / Consolas），深色默认，几乎零圆角零阴影，分隔线全用 border-dashed border-zinc-500。按钮就是一个字符：⟳刷新 ⨯关闭/删除 ✓确认 ↑↓移动 ◧◫复制 ○◉状态 - 最小化 ↓↑展开。颜色只有四档语义：zinc(忽略) green(安全) yellow(注意) red(危险)，外加 blue=A 腿、orange=B 腿贯穿全站（差价图、资金费面板高亮都用这两色）。

**怎么实现**: Tailwind，dark: 前缀双主题，主题可设 Auto/Light/Dark。

**判断**: A=蓝 B=橙 这条颜色约定贯穿列表、图表、面板，让用户不用读文字就知道在看哪条腿——这是最该抄的一致性规则。等宽字体让数字列天然对齐，做金融表格几乎是必选。但字符按钮是明显短板：⟳⨯◧◫ 对新用户毫无可发现性，文档不得不用一整页解释每个符号，我们应该保留密度但给按钮加 tooltip。

### （短板）零移动端、零响应式

**是什么**: trade 页外层硬写 `min-w-254`（未选中 ticker）或 `min-w-358`（选中后），差价图 dialog 最小宽 1016px。窄屏只能横向滚动。只有两处极简响应式：均价列在 <2xl 隐藏、屏宽 ≤1536 时按修饰键用均价顶替风险列。官方给的移动方案是——买台 Windows 服务器远程桌面连上去。

**怎么实现**: Tailwind 固定 min-width，无 breakpoint 布局切换。

**判断**: 明确的可攻击面。套利用户最需要移动端的时刻恰恰是出门在外仓位出问题时。我们至少要做一个只读的移动端监控视图（持仓 + 敞口 + 风险 + 一键平仓），不必做完整下单。

### Linux 一键部署：Docker Swarm + Tailscale + VNC

**是什么**: `curl -fsSL https://taoli.tools/setup | sh` 一条命令搞定：写入自定义 seccomp profile 到 `/etc/docker/daemon.json`、装 Docker、生成自签 TLS 证书（CN=signer）、`docker swarm init`、拉取 container 和 signer 两个镜像、`docker stack deploy`，最后 `rm -f keychain.toml KEY.pem` 删掉明文密钥（转成 docker secret 后销毁）。compose.yml 里两个 overlay 网络：`public`（container 用）和 `private`（**internal: true**，signer 只挂在这个内网上，外部完全不可达）。访问路径：Tailscale 组内网 → 本地浏览器访问 `https://<Tailscale内网IP>` 看到 VNC 里的 Chromium。

**怎么实现**: docker swarm secret 存 KEYCHAIN/CERT.pem/KEY.pem；`networks: private: {internal: true}` 让 signer 无出口；restart_policy `condition: any, delay 5s, max_attempts 0`（永久重启）；update_config `order: start-first`。坑：VNC **没有设置密码**，文档自己说「脱离 Tailscale 使用相当于裸奔」；关闭最后一个网页会导致 Docker Container 自动重启；申请交易所 API 的 IP 白名单要填云后台的**公网 IP** 而不是 Tailscale 内网 IP。

**判断**: 「signer 只挂 internal overlay 网络」这个隔离做得非常干净，是容器化部署密钥服务的标准答案。「明文 keychain.toml/KEY.pem 转 docker secret 后立即 rm」也是好习惯。但整套 VNC + Tailscale 方案是"纯前端工具必须有个浏览器在跑"的产物——**我们的 Python 后端根本不需要**，抄了是负债。只抄 docker secret + internal network 这两个点。

### 服务端只收集滥用检测数据

**是什么**: 明确列出收集范围：User Agent、IP 地址、交易所 UID 或钱包地址的 **Hash**（「Hash 可以用来检测数据是否重复，但由 Hash 并不能倒推出 UID 或地址」）、交易所资金额度。用途仅为账户滥用检测（配合 VIP 资金额上限）。不收集任何密钥和交易相关数据。

**判断**: 如果我们将来要做付费分级，「用 UID 的 hash 做跨实例去重、只上报聚合资金量」是一个隐私友好且够用的方案，可以直接抄这个设计。同时这份披露本身的写法（把收集的每一项都列出来 + 解释为什么 hash 不可逆）是好的合规文案范本。

### 导出：交易记录 / 交易小票 / 资金费 / 借贷利息，三种出口

**是什么**: 设置页第三列可导出四类历史：Trading（当日总表 + 按 Pair 的 A/B 分别筛的分表）、交易小票（SYMBOLS 和 EXCHANGES 默认隐藏，点击才展开）、Funding（最近 7 天资金费总表 + 按 Ticker 分表）、Lending（必须先选 Ticker 的杠杆借贷利息）。每类三种出口：浏览器内直接渲染 CSV / 通过 Telegram Bot 发送 CSV 文件 / 下载。

**判断**: maybe — 导出本身是基础功能，我们用 Python 做 CSV 是白菜价。真正值得注意的是**交易小票的打码晒单设计**：这是个社群增长杠杆（用户自发传播 + 不泄露策略），成本极低。资金费/借贷利息单独成表也合理，因为这两项是套利的真实收入/成本来源，混在交易记录里看不清。

### Loop 间隔语义：max(往返耗时, 设定间隔)

**是什么**: 设置里的 Loop Interval 是 Loop 时两笔下单之间的间隔。每个 Pair 内的下单是串行的，如果订单从发送到确认的耗时超过了设定间隔，下一笔立即发送。

**怎么实现**: 文档给了公式：实际下单间隔 = max(从下单到确认所需时间, Loop Interval)。另有 Display FPS 设置控制价格显示刷新频率，明确说明「只影响显示，不影响差价计算」。

**判断**: maybe — 语义值得抄（避免设了 100ms 就真的每 100ms 无脑打一发，堆积未确认订单）。Display FPS 与计算解耦这一点，对 NiceGUI 特别有用：UI 刷新频率和策略循环频率必须彻底分开，否则前端会拖垮后端。这条更像实现注意事项而非功能。

**是什么**: 按住修饰键后出现的按钮：复制出一个相同的 Pair 但 A 和 B 交换位置，同时 N 自动变为倒数、MinA 和 MaxA 自动对调、Sequence 也相应翻转。另有普通复制、上移/下移（右键置顶/置底）、最小化、删除（删除只是从界面消失，不影响实际持仓）。

**怎么实现**: Once 或 Loop 等待下单时不能移动位置。

**判断**: maybe — 纯效率糖，但那个「交换时所有关联参数自动同步变换」的细节说明作者踩过手动改错的坑。我们如果做多交易对面板可以抄。优先级低。

### 现货杠杆借贷利息的展示与核算（注意：仅记账，无借贷策略）

**是什么**: 现货杠杆腿的 Fee 位置显示每小时利息，点击查看利息历史。设置页可导出 Lending 现货杠杆借贷利息记录 CSV（必须先选 Ticker）。程序会拉 binance-cross-margin-info 和 backpack borrowLend/markets。

**怎么实现**: 导出 CSV 表头实测为 `Coin, Interest, Hourly Rate, Time` 和 `Time,Hourly Interest Rate,...`。各所借贷利息接口全覆盖：binance sapi/papi marginInterestHistory、bitget crossed/isolated interest-history、gate margin/uni interest_records、gate unified/interest_records、okx account/interest-accrued。

**判断**: 这是回答"它有没有借贷利差玩法"的确切答案：**没有**。它只做到了"如果你用现货杠杆腿做对冲，我帮你把借币利息算进成本"这个记账层级，没有任何"借 A 币放 B 池吃利差"的策略功能。对我们的价值是：如果我们支持杠杆腿（比如空现货），必须把小时利息算进净收益，否则年化会系统性高估。但不要为此专门做一个借贷模块。

### TradFi（美股/指数永续）跨所对冲

**是什么**: 支持表里除了永续/现货/现货杠杆，还有独立的 TradFi 列：Binance、Coinbase、Kraken、Bybit、OKX、Bitget、Backpack、Gate、KuCoin、HTX、MEXC 全部支持，Perp DEX 里 Hyperliquid/Aster/Grvt/Paradex/Pacifica/StandX 也支持。程序实测会拉 gate.com 的 tradfi-api/v1/symbols/detail。

**怎么实现**: Gate 的 TradFi 需要先在交易所内同意相关条款，API 才会返回。文档警告：TradFi 的开仓和平仓 Size 不一致会导致 PnL 计算出错。

**判断**: 这是一个 qqq.bot 完全没有的独立赛道——美股永续在各所间的价差和资金费差比主流币大得多（做市商少、定价效率低），而且和 crypto 行情低相关。但它有交易时段、分红调整、条款同意等一堆特殊逻辑，不适合 v1 就做。先记在路线图上，等我们六所主流币对冲跑稳了再评估。

### 开发者激励计划（把机会发现外包给社区）

**是什么**: 官方用免费 VIP2 换社区开发者做周边小工具，条件是"不收费"且"功能与 Taoli Tools 不重叠"。付费群每月投票，前 N 名（N = 群人数×3%，且票数 ≥ 群人数×9%）得一个月免费 VIP2。2025-05 至 2025-12 有完整获奖名单，2026 年 1 月已暂停。产出的工具包括：实时差价 taoli.live、CEX-DEX 套利监控 taoli.ducks.life/cex、套利监控系统 taolimonitor.life、交易所价格比较 exp-taoli.vercel.app、价差监控 TG 通知、充提状态&指数成分查询 bot（币探）、收益计算机器人（会计 u_calc_bot）、新币 bot、跨链桥。

**怎么实现**: 文档 third-party-tools.md 长期挂着这批第三方工具的入口。

**判断**: 这份名单是反向需求清单——社区自己动手补的，就是主产品缺的：**跨所价差实时监控榜、充提状态监控、收益计算器、新币上线提醒**。注意"收益计算器"是第三方 bot 做的，说明主产品确实没有；"充提状态"（能不能提币到另一个所）是跨所搬砖的硬前置，主产品也没有。我们做的时候应该把这几样直接内建，而不是重复它"外包出去"的路径。

### 设置页三列布局 + 导出/导入配置加密

**是什么**: Settings 分三列。第一列：账户信息（UID / VIP 等级 / 到期时间 / 资金上限 / 现资金额 / 总资金额，点数字弹出明细 CSV）、通知设置、通用设置（主题/语言/修饰键/显示帧率/循环间隔/高性能数据库开关）、外链和版本号、导出/导入。第二列：交易所（Unique Name + 下拉选所 + Add，保存后绿字显示资金量、红字显示报错）、区块链（RPCs/滑点/Gas 倍数/Bundle）、代币。第三列：历史记录导出（Trading / Funding / Lending 三个 tab）。

**怎么实现**: 导出会下载一个 json 并把一个 `tt-` 开头的密钥字符串复制到剪贴板，导入时需要同时提供文件和密钥；本地存储的 API Key/Secret 用 localStorage 里一个 randomUUID 派生的 AES-GCM 密钥加密（前缀 `encv1:`）。设置页在 trade 页里是通过 `<iframe src="/settings">` 嵌入的，URL 为 `/trade?settings=1`；按住任意修饰键点 Settings 则用 window.open 单开一个窗口。

**判断**: 三列布局把「账户/连接/导出」这三类完全不同的配置一屏铺开，不用切 tab，在宽屏工作站上是对的。导出配置需要单独密钥这一点值得抄（防止用户把带 API Key 的 json 随手丢群里）。iframe 嵌设置是个偷懒实现，我们用 NiceGUI 的 dialog/drawer 更干净。

### 私钥/助记词拆成 Head + Tail 两个输入框

**是什么**: 所有 DEX/链上账户的凭据输入，不是一个长输入框，而是 `Private Key Head:` 和 `Private Key Tail:` 两个 password 框（助记词同理 Mnemonic Head/Tail，各自 minLength 6），存储时也分成 privateKeyHead/privateKeyTail 两个字段。

**怎么实现**: 两段在使用时才拼接；配合可选的 Signer 模式（填 Signer URL + Signer Secret，密钥根本不进浏览器）。

**判断**: 防剪贴板监听/防肩窥的低成本手法，用户必须分两次粘贴，恶意扩展一次读取拿不到完整私钥。我们的工具是 Python 本地跑，风险模型不同，但如果以后加链上腿可以直接用这个模式；即使只有 CEX，API Secret 也可以照做。


## SKIP (10)

### 浏览器多开隔离（--user-data-dir）

**是什么**: 购买 VIP 后可在任意个浏览器环境中使用，每个环境只计算和显示当前环境中添加的交易所资金额度，但**服务器后台会统计不同浏览器环境的交易所资金总额**（用于卡 VIP 额度）。同机多开方法：`chrome.exe --user-data-dir="C:\Taoli Tools 1"`、`"C:\Taoli Tools 2"`，一个文件夹路径对应一个独立浏览器环境。

**怎么实现**: `chrome.exe --user-data-dir="<path>"`，Windows/macOS/Linux 各给了命令。服务端按交易所 UID 的 hash 去重后汇总资金量。

**判断**: 这是"多账户管理"在纯前端架构下的替代品——不是产品功能，是操作技巧。**反面教材**：我们用 Python 后端可以在一个进程里管理 N 个账户，天然优于这种物理隔离。但要注意它暴露的一个真实需求：用户确实会跑多组互不干扰的策略实例，我们应该支持"策略实例"或"配置档"概念。另外 FAQ #13「重启后之前配置好的交易所都没了」的原因之一就是没用同样的 `--user-data-dir` 启动——这种脆弱性正是我们要避免的。

### CORS 解除方案（浏览器插件 / 命令行）

**是什么**: 因为浏览器跨域限制，必须解除才能用；Binance、Gate、Bitget 三家被明确标注「因 API 限制，必须解除跨域限制才可以使用」。两个方案：(1) 官方 Chrome 插件（MV3，`declarativeNetRequest` 权限 + `host_permissions: ["*://*/*"]`，background service worker 里跑一个 `EXTENSION_PROXY_FETCH` 消息代理转发 fetch，10 秒超时；urlFilters 硬编码了 gate/bitget/binance/coinbase/okx/bybit/mexc/backpack/asterdex/grvt/pacifica/extended/standx/apex/48club/larksuite）；(2) 命令行 `--disable-web-security --user-data-dir="..."`。

**怎么实现**: MV3 插件用 declarativeNetRequest 改响应头 + background fetch 代理；或 Chromium 启动参数 `--disable-web-security` 配合独立 `--user-data-dir`。

**判断**: **纯反面教材，绝对不要抄**。这是"把交易逻辑放浏览器"这个架构决策付出的最大代价：要求用户装一个拥有 `*://*/*` 全站权限的插件，或者关掉浏览器最核心的安全机制——这本身就和它风险页里"恶意插件会偷走你的 API Key"的警告自相矛盾。Python + NiceGUI 的 HTTP 请求走后端，**零 CORS 问题**，这是我们相对 taoli.tools 的结构性优势，应该在宣传里明说。

### 数据持久化：只有浏览器本地存储，无服务端

**是什么**: 除 Telegram 用户信息和登录信息外，所有数据存在本机浏览器，API Key/Secret「有一层简单的加密」。换浏览器 = 全部要重加；清缓存 = 全部消失；FAQ #13 补充了第三种丢失原因：「没有使用和之前一样的方式打开浏览器，或者硬盘剩余空间不足，浏览器清理了数据」。另有 P&L High-performance DB 开关（只支持 Chrome/Edge/Firefox），警告「勾选后一个浏览器中不可以同时打开两个版本不一致的网页，否则可能导致数据库卡住」。

**怎么实现**: localStorage/IndexedDB；P&L 走高性能 DB（推测 OPFS 或 IndexedDB）；无云同步、无服务端备份、无导出数据库文件的能力（只能导出 CSV 报表和 Settings JSON）。

**判断**: **这是 taoli.tools 最大的运维短板，也是我们最容易赢的地方**。跨所套利用户的 P&L 和对账数据积累几个月后价值极高，存在一个随时可能被浏览器清掉的 IndexedDB 里是不可接受的。我们用 SQLite + 定期备份，加上"配置包导出"，可以直接把这条当卖点。「不收集任何密钥和交易相关的数据」的隐私姿态倒是值得学（我们本地跑天然满足）。

**判断**: skip — 这条是**负结果，专门用来止损**：不要再花时间去 taoli.tools 找这些功能，它没有。这也解释了两个产品的分工——taoli.tools 明确不做自动化（既是产品定位也是免责盾牌），qqq.bot 的策略引擎/自动降杠杆/ADL 自动响应恰好补的就是这块。我们的工具应该是「taoli.tools 的看板与执行原语 + qqq.bot 的自动化」，两边各取一半。

### （不抄）浏览器架构的三件包袱：解除 CORS / 自建 /proxy 中转 / Signer 服务

**是什么**: 因为整个工具跑在浏览器里，它被迫做了三件我们完全不需要的事：(1) 用户必须解除浏览器跨域限制才能用（装它自研的浏览器插件，或用 --disable-web-security 命令行启动，后者会一直显示安全警告）；(2) 自建 https://taoli.tools/proxy?url=<urlencoded> 中转那些不发 CORS 头的交易所接口；(3) 做了独立开源项目 Taoli Tools Signer，把助记词从浏览器里挪出来变成自托管签名服务。

**怎么实现**: 我实测确认 /proxy?url= 端点存在且工作（Gate、Coinbase、Kraken、Backpack、Ondo 等走代理，Binance/OKX/Bybit/Bitget 直连）。另有自建缓存端点 /binance-open-interests、/binance-cross-margin-info、/grvt-tickers、/stand-x-tickers、/apex-omni-tickers。Signer 支持 EVM + Solana，特性含多钱包、IP 限制、**合约白名单**，可部署到 Cloudflare Workers 或 Docker Swarm（用 docker secret 存 keychain）。部署方式三选一：本地浏览器 / Windows 服务器远程桌面 / Linux Docker + VNC，一行安装 curl -fsSL https://taoli.tools/setup | sh。

**判断**: skip — 这是**我们的结构性优势，不是待抄清单**。Python 后端没有同源策略，直连所有交易所，不需要插件、不需要代理、不需要把密钥挪来挪去，也不需要教用户开 VNC 或远程桌面。要认识到：taoli.tools 相当一部分复杂度是在偿还「跑在浏览器里」的债，我们可以只拿它的功能设计（VA/VB、Risks、Flat、榜单列），把架构代价全部跳过。唯一值得借鉴的一点是它的 API Key 安全纪律：只给读取和交易权限、**绝不给转账提现**、开 IP 白名单——并且它诚实指出即使这样，黑客仍可通过小币种对敲转移资金。

### 多浏览器环境多开（批量账户的土办法）

### 浏览器扩展 taoli-tools-extension（CORS 解药，不是功能）

**是什么**: Chrome/Edge 扩展，唯一作用是让纯前端网页能直连交易所 REST API。它做两件事：① 用 declarativeNetRequest 对 18 个域名（binance.com/okx.com/bybit.com/bitget.com/gate.io/gate.com/gateio.ws/mexc.com/coinbase.com/backpack.exchange/asterdex.com/grvt.io/pacifica.fi/extended.exchange/standx.com/apex.exchange/48.club/larksuite.com）改写 origin 和 referer 请求头为该域名自身；② 提供一个 background fetch 代理，页面 postMessage 一个请求，content script 转给 background 用扩展权限发出去，返回 status/statusText/headers/text，10 秒超时。content script 只注入 taoli.tools 和 localhost:5173，并在页面里挂 `window.TaoliToolsExtension = {}` 供网页做能力探测。点扩展图标就打开 taoli.tools。备选方案是命令行 `--disable-web-security` 启动浏览器。

**怎么实现**: MV3，permissions 只要 declarativeNetRequest，host_permissions 是 */*。规则 id 按数组下标 1..18，onInstalled/onStartup 都重刷一遍动态规则。

**判断**: 对我们零价值——我们是 Python 后端，本来就没有同源限制。但它有两个信息量：(1) 它暴露了「纯前端本地运行」这条路线的真实成本，用户必须装扩展或改浏览器启动参数，文档里专门有一整章教这个，这是我们相对它的天然优势，应该在定位上强调；(2) 那 18 个域名列表等于它支持的交易所直连清单，可以当我们的接入优先级参考。

### Docker + noVNC 容器（服务器部署形态）

**是什么**: taoli-tools-container 仓库：Alpine + openbox + TigerVNC + Chromium + noVNC + websockify + Tailscale + Noto CJK 字体，时区写死上海。用户 `curl -fsSL https://taoli.tools/setup | sh` 一键起 docker service，然后浏览器打开 https 直接看到远程桌面里的 Chromium。定制的 noVNC index.html 加了一个关键补丁：拦截 Ctrl/Cmd+V，读本地剪贴板后按字符模拟按键打进 VNC 会话（自动处理 Shift 和 CapsLock）。

**怎么实现**: rfb.resizeSession=true, qualityLevel=0, compressionLevel=9；粘贴前先松开 Control/Meta 再延迟 500ms 逐字符 sendKey。

**判断**: 这个「远程桌面里跑浏览器」的形态完全是被前端架构逼出来的（要 7x24 又要本地存密钥）。我们是 Python 服务，直接后台常驻 + Web UI 就行，不需要它。唯一有价值的洞察是那个剪贴板补丁揭示的痛点：远程环境粘贴 API Key 很痛苦——我们的 Web UI 天然没这问题，可以作为卖点。
